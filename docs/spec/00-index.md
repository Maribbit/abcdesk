# 规格总索引

`docs/spec/` 是唯一验收契约。`docs/archive/` 中的 D0 文档仅为历史冻结副本，不具规范性。

## ID 规范

- 格式：`SPEC-<域>-<两位序号>`（域为大写字母，如 `CMD`、`PLAY`）。
- 序号从 01 起，两位数字；ID 一旦分配永不回收、不复用、不重排。
- 废弃条目保留原文并标注"已废弃"及原因，不删除。
- 条目以 `### SPEC-... 标题` 三级标题定义，块内为固定字段列表。

## 条目模板

```text
### SPEC-CMD-01 公开命令恰为八个
- 规范：（可测断言的语义：无歧义、可判定）
- 验证：auto（或 manual，二选一写实际采用的一种）
- 里程碑：M0（首次应当满足的里程碑）
- 依据：D0 设计 §2（追溯来源）
```

## 验证方式与双向绑定

- `auto`：条目必须被 `src/**/*.test.ts` 或 `test/**/*.test.ts` 中带 `[SPEC-域-序号]` 前缀的测试（含 `it.todo` 占位）引用。
- `manual`：条目必须在 `docs/manual-checks.md` 中以 `[SPEC-域-序号]` 登记（含步骤与判据）。
- `npm run spec:check` 双向校验：无未绑定条目、无悬空引用、无重复定义、无缺"验证"字段。
- 变更流程见 `docs/conventions.md`。
