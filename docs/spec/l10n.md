# L10N：本地化与文案

> 依据：D0 设计 §8（本地化与文案）；计划 §5 第 17 条；§7 清单第 17 项与"M1 布局与本地化验收补充"。
> M0 验证三条文案路径与代表性文案；全量中英覆盖与术语一致性在 M1 验收。
> 全部条目采用 manual 验证（登记见 `docs/manual-checks.md`）。

### SPEC-L10N-01 语言策略与回退
- 规范：英文作为默认文案，首版同步维护简体中文（zh-CN）的自有界面文案，跟随 VS Code 显示语言；不支持的语言或缺失翻译回退英文，不显示资源键或空白标签；不增加插件语言设置、切换命令或在线翻译；语言变更沿用 VS Code 的切换 / 重载流程，不承诺独立热切换；VS Code 原生对话框（保存等）沿用宿主语言，不由插件重写。
- 验证：manual
- 里程碑：M0
- 依据：设计 §8；计划 §5 第 17 条

### SPEC-L10N-02 三条文案路径与语言来源
- 规范：声明式贡献（命令 / 设置）从第一天抽取文案并使用 `package.nls.json` 及语言资源；扩展运行时提示使用 VS Code l10n；webview 显式接入随扩展打包的文案资源，不假设宿主会自动翻译其 DOM；语言来源统一为 VS Code 显示语言，Remote 下不改用远端系统语言或 webview 的浏览器语言；M0 以代表性文案验证三条路径在英文、简体中文与未支持语言下的一致选择与英文回退，并检查资源打包、占位参数、安全文本与无外部请求。
- 验证：manual
- 里程碑：M0
- 依据：设计 §8；计划 §7 清单第 17 项

### SPEC-L10N-03 不翻译清单与持久标识
- 规范：`ABC Desk`、命令 / 设置 ID、ABC 指令、MIDI / SVG 等技术名称不翻译；文件路径、用户曲名、声部名与学习材料保持原文，不自动翻译 ABC 或修改导出中的用户内容；持久标识、状态枚举与消息类型不依赖本地化后的显示文字；设计文档中的中文线框与名称仅用于表达语义，不要求英文环境显示中文。
- 验证：manual
- 里程碑：M0
- 依据：设计 §8

### SPEC-L10N-04 文案风格与术语语义
- 规范：命令与动作按钮使用明确动作、提示使用短句，按需要说明"发生了什么、影响什么、接下来能做什么"；只呈现当前真实可用的操作，不把未知原因写成确定结论、不伪造进度、不暗示已听到用户演奏；"暂停""停止并回到开头""隐藏提示""静音"保持不同语义、不笼统写成"关闭"；重试会起播时明确写"重试并播放"；同一动作在命令、控件、提示与无障碍名称中语义一致；设置说明交代作用与保存边界；示例（"无法准备音频。谱面仍可查看。"搭配"重试并播放"；"文件已更新。暂停后应用新版本并回到开头。"）按实际状态使用，不能在谱面也失效时声称仍可查看当前谱。
- 验证：manual
- 里程碑：M0
- 依据：设计 §8

### SPEC-L10N-05 第三方错误摘要与原始详情
- 规范：第三方错误使用本地化摘要 + 可展开的原始详情，不承诺翻译 abcjs 或系统的全部原始报错；能可靠分类时说明具体问题，不能分类时按失败阶段给出通用摘要（如"无法解析乐谱"），不猜测行号、权限或网络原因；预览使用既有详情区，无预览导出失败也提供可查看原始详情的入口、不为查看错误强制打开音乐预览；Problems 的可靠位置与严重性沿用诊断规则，仅展示摘要不足以排查时保留原文供查看，不把全部错误粗化成同一条诊断；原始消息可保留原语言，主提示不直接堆放堆栈；动态参数、文件内容与第三方原文均按文本安全呈现，不因本地化包装拼接 HTML；不在线翻译、不上传错误、不自动生成日志文件；本地化不改变诊断位置、严重性或可用操作。
- 验证：manual
- 里程碑：M0
- 依据：设计 §8；计划 §7 清单第 17 项

### SPEC-L10N-06 覆盖范围与同步维护
- 规范：首版覆盖八个命令的显示名称、菜单、设置说明、预览控件、工具提示、状态 / 错误 / 空状态、导出流程的自有提示、无障碍标签与状态播报；新增或修改自有文案时同步维护中英版本；M1 完成全量中英覆盖、术语一致、窄面板长文案与缺译回退检查；商店材料、完整双语文档与其他语言后置。
- 验证：manual
- 里程碑：M1
- 依据：设计 §8；计划 §7（M1 布局与本地化验收补充）
