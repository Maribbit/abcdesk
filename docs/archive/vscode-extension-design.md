## 2. 入口与信息架构

- [x] ★ 主入口：用户主动打开预览；第一版不提供随打开 ABC 自动预览的行为或设置。
  - 三个直接打开入口：ABC 编辑器标题栏按钮、命令面板“ABC Desk: 打开音乐预览到侧边”、资源管理器 `.abc` 文件右键菜单，共用 `abcdesk.openPreviewToSide`。
  - 首次在侧边创建；同文件已有预览时显示并复用，不重复创建。资源管理器入口不要求先打开源码；命令面板没有当前 ABC 目标时允许选择一个文件，取消不创建预览。
  - 主动播放的按需打开：从 ABC 编辑器执行“播放／暂停”的播放分支或“从光标播放”，可在侧边创建或显示对应预览，保留源码焦点；渲染与音频准备完成后，仅执行仍有效的请求。“从光标播放”无有效映射时提示，不改为从头播放；普通播放仍使用播放位置。停止等非起播操作不为控制音乐新建预览。
  - 按需打开是用户明确播放请求的一部分，不放开被动自动打开；打开文件、切换编辑器、外部 agent 修改或已关闭文件的内容变化均不触发预览打开。预览隐藏时，明确起播须先显示对应预览，不提供隐藏面板后台发声。
  - 非播放期间按对应文档变化自动更新（含未保存修改），受 §3 的大材料确认、主动取消与超时规则约束；播放期间保留当前版本、暂停后更新（见 §5），均不自动起播。恢复先前已打开的预览与自动新建预览分别处理，不借恢复自动重试已取消的准备。
- [x] ★ 预览形态：采用原生文本编辑器 + Editor 区独立音乐预览页（Markdown preview 式）；第一版不注册 Custom Editor。
  - 编辑时支持源码与预览并排；练习时可单独显示、放大同一个预览页，不要求源码标签页一直打开，不另建练习模式页面。
  - 预览明确显示来源文件（如“预览：exercise.abc”）；切到学习记录或 AI 对话不丢失当前练习。控件布局见 §3，按键与焦点原则见 §4，基础命令表见下方；具体尺寸仍待细化。
  - 撤除提示在预览内部完成，保留播放控制；AI 对话由外部 agent 提供，可位于编辑器内或编辑器外，不由本插件提供或控制其位置。
- [x] ★ 命令集范围：第一版仅公开下表八个基础命令，命令分组为 `ABC Desk`、ID 前缀为 `abcdesk.`；可在相关上下文的命令面板发现并自行绑定，不新增工作台级默认组合键。
  - 不增加“停止本窗口音乐”、隐藏 / 显示提示或循环切换的公开命令；后两项继续通过预览控件操作。停止只控制明确目标，不回退到本窗口正在播放的其他文件。
  - 从光标播放与从所选音符播放使用两个独立命令，避免混用源码光标与谱面选择；预览按钮仍可简写为“从此处播放”。
- [x] 预览与文件的对应关系：每文件绑定预览，同文件复用。
  - 在同一 VS Code 窗口内，同文件的打开请求复用已有预览；切换活动编辑器（包括其他 ABC）不改变绑定。
  - 主动预览另一个文件时，打开其独立预览，不替换当前练习；第一版不增加自动跟随 / 固定开关。
  - 多预览在同一窗口内播放互斥：新播放先暂停旧播放；面板隐藏暂停、关闭停止并释放资源；播放中文件更新保留当前版本到暂停后应用（见 §5）。
- [ ] 侧栏容器与 TreeView（会话、练习库）：放活动栏还是资源管理器（后置到 P1，见计划 §4）
- [x] 状态栏：首版不加任何状态栏项。播放状态、速度、当前曲目已在预览控制区；多预览时状态栏无法说清对应哪个预览，且“同窗口单预览发声、隐藏即暂停”已排除“看不到预览却在响”的场景。“仅发声时显示一项”等形态留待自用实验证明需要后再评估，不先加后删。
- [x] 激活事件：仅 `onLanguage:abc`，加上 `contributes.commands` 自动生成的命令激活（VS Code 1.74+，不手写 `onCommand`）；不使用 `workspaceContains`、`onStartupFinished` 或 `*`。
  - 菜单、命令、语法高亮与文件关联为声明式贡献，未激活时已可见；未打开 ABC 的工作区零开销，不扫描工作区文件。首版没有提前激活可做的事：不建索引，诊断仅面向已打开文档。
  - 资源管理器右键未打开的 `.abc` 时，激活发生在点击命令那一刻，接受首次多几百毫秒；激活本身不创建预览、不加载音色、不弹通知。激活耗时在 M0 记录，属于计划 §1 质量基线。
- [ ] 菜单贡献点细节：预览入口已确定为编辑器标题栏与资源管理器右键；具体图标、分组及 `when` / `enablement` 表达式待实现，语义按下表与目标规则执行。

### 基础命令表

命令面板名称均以 `ABC Desk:` 为分组前缀。下表使用简体中文名称记录首版公开 ID 与交互约束；显示名称按 §8 本地化，品牌、ID 与命令数量不变，不表示已经注册或通过运行验证。

| 名称 | 命令 ID | 上下文与行为 |
| --- | --- | --- |
| 打开音乐预览到侧边 | `abcdesk.openPreviewToSide` | 明确文件、当前 ABC 源码或预览；无目标时选择一个 ABC 文件。创建 / 复用并显示预览，进入预览，不起播 |
| 播放／暂停 | `abcdesk.togglePlayback` | 当前 ABC 源码或预览；控制当前曲目，不跟随光标切曲；播放分支可按需显示预览并保留源码焦点，首次默认第一首。起播准备中再次执行取消起播并保留已提交位置，内部缓冲中执行则暂停并取消续播；有待更新文档按暂停规则应用并归零，无有效选曲时提示选择 |
| 停止并回到开头 | `abcdesk.stop` | 目标预览或起播请求存在；停音、回到当前曲目开头、取消起播，不改选第一首，不要求最新内容可解析，也不新建预览 |
| 从光标播放 | `abcdesk.playFromCursor` | 当前 ABC 源码的光标；可靠确定曲目与音符时可显式跨曲起播，按需打开预览并保留源码焦点；无有效映射不切曲或从头播放，不绕过待更新规则 |
| 从所选音符播放 | `abcdesk.playFromSelectedNote` | 当前预览的有效音符选择与起播映射；不借用旁边源码的光标，不播放失败后的只读旧谱 |
| 转到源码编辑 | `abcdesk.goToSource` | 当前预览的来源文档；显式转移焦点。无有效音符映射时只打开来源文件，不套用旧偏移 |
| 导出 MIDI | `abcdesk.exportMidi` | 目标 ABC 源码或预览所绑定文档的当前内容（含未保存修改）；多曲目每次确认一首；仅按 ABC 材料，不应用播放器练习设置，不起播、不代为保存 ABC |
| 导出 SVG | `abcdesk.exportSvg` | 目标 ABC 源码或预览所绑定文档的当前内容（含未保存修改）；多曲目每次确认一首；导出白底黑谱，不含交互标记，不使用旧参考谱 |

### 目标解析与可用性规则

- 明确目标优先：编辑器 / 资源管理器菜单传入的文件，以及预览按钮所属面板，确定此次目标；目标无效或已销毁时不回退到另一个文件。
- 无显式目标时，使用调用前的活动编辑器上下文：音乐预览绑定的文件，或当前 ABC 文本文档。预览在前台时不能因为另一组仍保留源码编辑器对象就误选源码文件。
- 命令面板临时获得焦点不改变调用前的音乐上下文；学习记录、其他语言文件或无编辑器时视为无目标，不回退到最近使用 / 最近播放的预览，不弹预览选择器。普通控制命令不可用，直接调用时说明缺少目标且无副作用；仅“打开音乐预览到侧边”允许文件选择。
- 每个命令仍须满足其上下文要求：“从光标播放”不能拿预览背后残留的源码光标，“从所选音符播放”不能把源码选区当成谱面选择。多个文件同名时按文档标识区分，不按显示名匹配。
- 迁移冲突后的来源状态页不再是可控音乐目标，不执行旧绑定的播放、定位、设置修改或导出，也不把命令静默转交目标文件；只能通过明确的目标预览入口重新进入正常目标解析（§6）。
- 语言模式为 ABC 的未保存新文档也属于有效源码目标，沿用现有打开 / 播放命令，不增加新命令或强制保存步骤；预览标明“尚未保存”。首次保存、另存为、重命名与来源不可用的绑定规则见 §6；目标存在与能力可用仍须分别校验。
- 播放命令按需打开后，起播仍受有效版本、映射、面板可见性与单窗口互斥约束；已有播放快照待更新时，源码起播不得绕过暂停后应用更新的规则。渲染 / 音频准备期间请求取消或目标失效，不得静默改控其他版本或文件。
- 命令与预览按钮共用操作规则；菜单可见性、命令启用条件和执行时校验分别处理，不能仅凭隐藏 / 禁用入口保证安全。停止和取消请求不因音频尚未就绪或内容错误而失效。
- 不增加窗口级停止命令；在学习记录等无目标页面需要停音时，先回到对应 ABC 源码或预览，再使用停止 / 暂停。
- 导出使用命令执行时目标文档的当前内容快照，不使用落后的播放 / 预览版本；包含未保存修改，不代为保存 ABC。无预览时也应独立准备数据，不要求先播放、加载音色或显示音乐预览；无有效输出时说明原因，不回退旧数据。版本校验、MIDI / SVG 语义与保存流程见 §3，不扩展批量导出或新增命令。
- 目标规则已定；具体上下文键、`when` / `enablement` 表达式、源光标采样与异步请求绑定由实现落实，并在 M0 验证命令面板、多个编辑器组、右键参数与过期目标场景。

## 3. 核心交互（编辑–预览–播放回路）

- [x] ★ 基础三方联动：查阅位置与播放位置分离；播放时只跟随谱面滚动。
  - 点击谱面音符：选中音符、定位对应源码，焦点留在预览，不改变播放位置，不额外发声；通过显式“转到源码编辑”才转移焦点（见 §4）。需要试听时显式执行“从光标 / 所选音符播放”；普通播放 / 暂停控制当前播放位置，不因查阅选中另一音符而跳转。
  - 停止 / 暂停时移动源码光标：属于当前曲目时突出对应谱面元素，必要时滚动使其可见；光标属于其他曲目时不自动切曲或套用当前曲目的映射，可提示目标曲目。播放位置不变，不自动起播。
  - 播放时移动源码光标：更新查阅标记，不改变音乐，不抢占播放跟随的滚动。
  - 播放过程：更新谱面、键盘与源码的播放高亮；不移动编辑光标、不自动滚动源码、不因播放打开已关闭的源码页。查阅标记与播放高亮需可区分，不只靠颜色区别。
  - 谱面播放位置超出可视区域时自动滚动；用户手动滚动谱面后暂停自动跟随，提供显式“恢复跟随”操作。这里的跟随仅指谱面滚动，不涉及切换文件。
  - 已隐藏的谱面 / 键盘提示不因光标或播放事件重新显示；文件变化不自动起播。
- [ ] 映射与联动验证：在 M0 验证反复记号、多声部及查阅 / 播放标记共存；防抖、具体控件与焦点细节后续细化。
  - 待决策 P02：显式“从此处播放”遇到反复音符时，推荐使用演奏序列中的第一次出现，但尚未确认默认落点；不把推荐当成最终规则。多声部按所选时刻及现有静音设置播放，不自动独奏；无有效映射时提示，不悄悄从头播放。
  - 播放中文件变化时保留旧音乐与旧谱，立即停用源码联动；暂停后应用最新版本（见 §5），不得用旧字符范围定位新文本。
- [x] 预览区域布局：正常高度采用顶部控制区、中央独立滚动谱面、底部可收起的键盘，控制区与展开的键盘保持可见；低高度时采用下方“窄窗口与低高度适配”的整体滚动例外，不强求谱面和键盘同时可见。主要播放控件位于 webview 内，不分散到原生标题栏或全局状态栏；原生标题栏保留打开预览等编辑器入口。
  - 常用播放操作：播放 / 暂停、停止、循环、速度、进度。
  - 查阅与练习操作：从此处播放、声部、隐藏提示；无有效定位时禁用“从此处播放”并说明原因。
  - 低频操作：MIDI / SVG 导出等收入“更多”。窄预览下常用控件按稳定分组换行，不因宽度变窄把循环、速度、声部或隐藏提示收入二级菜单；进度独占一行。播放 / 暂停、停止及关键状态不得藏入“更多”；不因尺寸变化自动撤除键盘提示。
- [x] ★ 两种“关闭示范”的入口独立：声部菜单控制声音，“隐藏提示 / 显示提示”按钮控制视觉，不以单一练习模式同时改变两者。
  - 声部使用折叠菜单，提供各声部发声开关；菜单关闭时仍显示静音摘要，例如“已静音 1 个声部”。展示 ABC 实际声部，不强制第一声部为示范；模板可用“示范 / 伴奏”作为显示名称。
  - 自动生成的和弦伴奏轨有独立控制，不与显式 ABC 伴奏声部混为一谈。
  - 隐藏提示一次隐藏谱面与键盘，保留控制区、进度与状态信息；不改变声部静音状态、不暂停音乐。恢复提示时还原之前的显示状态，例如原先收起的键盘仍保持收起。
  - 隐藏提示只作用于预览，不隐藏原生源码；用户可自行切走源码页练习。
- [x] 速度表达与应用：百分比为主控，默认 100%，范围 25%～200%；支持输入与“恢复原速”（100%），只调整试听、不修改 ABC 速度标记。
  - 可可靠换算时辅助显示带拍单位的节拍速度，例如“速度 75%，四分音符 = 90”；曲中变速按所在位置解释，不能用一个无拍单位的 BPM 冒充整曲速度。无法可靠换算时不显示猜测值。

- [x] 进度定位：拖动预览、松手提交；进度条按含反复的实际演奏顺序展开，可定位第二次反复，与源码查阅位置分开。
  - 播放中拖动时原音乐继续，只预览目标时间；松手后执行一次定位并继续。暂停中拖动只改变下次起点、不发声；点击进度条直接定位，保持播放 / 暂停状态。
  - 取消拖动不提交位置；停止、隐藏、播放接替或自然结束等事件不得被后到的拖动提交覆盖，不得因此重新起播。拖动目标所属版本失效时取消该定位，不能套用到新版本。
- [x] 声部切换时机：第一版先暂停再调整；播放中菜单可查看，声部发声开关需暂停后才能修改，菜单提供“暂停以调整声部”入口；自动和弦伴奏开关遵循同一规则。
  - 没有文件更新时，暂停与连续调整多个声部保留乐曲位置；调整后由用户手动播放，不自动续播。需要从头练习时先回到开头。
  - 有待更新文件时，暂停先应用最新版本并重置到开头，随后调整新版本的声部；不能为保留位置而继续操作旧文档。声部清单可靠且未变才恢复静音，变化或无法确认时清除旧声部静音覆盖并提示，详见 §5。
- [x] 停止与循环基础语义：停止立即停音并回到开头；整段循环无保存设置时默认关闭，开关本身不启动播放。待更新内容仍按 §5 在停止时应用，循环回到开头不触发换版。
- [ ] 控件验证与细节：变速与进度保持演奏位置、提交输入的键盘 / 焦点交互、缓冲 / 失败状态、声部结构识别与恢复规则验证（见 §5）；从光标起播的版本与映射校验；入口与命令见 §2，选区循环后置。
- [x] 键盘初始显示：没有该文件的有效保存设置时默认展开；启用设置记忆且有记录时恢复该文件的展开 / 收起状态（见 §5）。同一预览内手动收起后，不因播放、声部切换或面板恢复而展开；“隐藏提示”恢复时还原原有展开 / 收起状态。
- [x] 键盘音域与适配：默认采用当前曲目整首记谱材料的音域，不合并文件内其他曲目；至少保留两个八度的参照空间，可切换完整 88 键（A0～C8）；标记各个 C 的八度，中央 C 标为 C4。
  - 音域按当前显示的文档版本计算，同版本内不随音符或声部静音变化而伸缩；播放中收到新文件版本时，不提前重排旧谱对应的键盘。
  - 窄窗口保持可辨认键宽，放不下时允许手动横向滚动，不强行压缩 88 键、不自动收起。播放不驱动键盘自动横移；可视窗口外有提示音时显示方向提示，不把手动浏览拉回播放位置。
  - 超出 A0～C8 的音符明确提示，不折返到其他八度冒充原音高。低高度时保持展开偏好并随内容纵向滚动；具体音域留白、键宽及无音高材料的状态仍待细化。
- [x] 键盘提示语义：跟随记谱材料的演奏时间，包含静音声部；标明“乐谱提示，含静音声部”。静音不撤掉对应键盘提示或谱面音符，谱面的时间跟随继续，由“隐藏提示”独立撤除视觉帮助。

- [x] 琴键操作：第一版仅作可视提示，不提供点击琴键试听；琴键不改变播放位置或谱面选择，不呈现可演奏按钮的暗示。
- [ ] 键盘实现验证与细节：音域边界算法、键宽与高度下限、低高度布局断点、方向提示、音高与演奏时间映射、非按钮形式的无障碍说明；初始显示、音域主策略、静音提示及低高度整体滚动语义已定。
- [x] 音频准备时机：先渲染乐谱，首次明确播放时再准备所需音色与音频；仅查看谱面不主动预备音频，已准备好的资源可复用。
  - 点击播放后显示“正在准备音频…”，成功后执行这次仍有效的播放请求，无需再点一次；准备期间再次普通播放／暂停会取消起播并保留最后已提交位置，不提交仍在准备的定位目标，“停止”则取消并归零。有待更新文档时按暂停规则应用并归零。

- [x] 最新内容渲染失败：保留上一次成功的谱面并明确标记“最新内容暂不可预览；下方为旧版本，仅供参考”；禁用旧谱播放与源码定位，清除播放标记和键盘动态提示。首次失败没有旧谱时显示错误占位。

  - 内容恢复有效后自动更新显示，不自动起播；错误与恢复不重新显示已隐藏提示。连续修改可防抖合并，但不推测“AI 正在生成”。
- [x] 音频失败按能力降级：当前谱面已经成功渲染、仅音频准备失败时，保留当前谱面及属于当前文档版本的可靠源码定位，仅限制依赖音频的操作；旧谱参考仍不得恢复源码联动。

- [x] 空状态与诊断原则：空白文件显示“文件尚无音乐内容”及“转到源码编辑”，不报红、不自动填入示例；合法全休止符乐谱不视为空文件，键盘可说明没有音高提示。

### 大材料、等待与取消

- [x] 分级保护：超过自动处理软阈值时，暂停本次自动预览，在状态区说明“大材料可能需要较长时间”，提供“继续预览”。确认仅授权当前文档版本与目标曲目的预览尝试，不跨版本记住，不授权音频或导出，也不绕过硬上限；确认时重新核验目标，已变化则更新提示，不沿用旧确认。进入该状态时取消原先等待渲染的起播请求，继续预览成功后仍需明确播放。
  - 后续内容版本仍超过软阈值时留在待确认状态，不因连续编辑反复弹窗或自动开始重任务；新版本回到自动处理范围后可按原规则更新，但不恢复旧起播。播放中的文档变化仍只标记待更新，到暂停 / 停止 / 自然结束才应用这些预览规则，不能借性能检查提前切版或中断当前音乐。
  - 超过安全硬上限时停止对应处理，说明受限能力与已知原因，建议用户手动缩小材料；不提供“强行继续”，不自动删音符、截取谱面、拆文件或输出不完整的成功结果。显式播放、重试与导出也遵守硬上限；首版不新增性能设置或公开命令。
- [x] 按阶段限制能力：整文件读取 / 解析、所选曲目渲染、音频准备与两种格式导出分别检查，不只按文件字节数判断。可用指标包括输入规模、解析 / 展开事件数、有限演奏时长与预计音频缓冲规模；音频预算考虑实际练习速度与采样参数，导出按自身材料与格式计算，不借用播放器设置。估算不得伪装成精确测量，不能为了检查上限先无界展开或分配完整缓冲。
  - 短文本也可能因大量反复、极慢速度或异常指令触发限制；播放器的整段循环不应被展开成无限音频。整文件层面无法安全读取 / 解析时，依赖它的能力不可用；曲目范围可可靠确定后，按目标曲目判断，不默默换成另一首。
  - 音频超限 / 超时保留当前有效谱面及可靠源码定位，独立导出按格式另行判断。新版预览等待确认、超限、取消或超时时，旧版仅供参考，不可播放或定位新源码；没有旧谱则保留相应状态占位。纯布局重排取消 / 超时可保留同版本有效谱面及可靠映射，不把它错误标为文档旧版。编辑与打开来源不受这些处理限制，不自动改写原文件或练习偏好。
- [x] 分阶段等待与超时：先显示真实阶段，较慢时补充仍在准备的说明与取消入口，不伪造百分比；音频慢提示明确“完成后将播放”，仅仍有效的起播请求可执行。渲染、音频准备、导出准备分别有明确时间上限，超时终止本次请求；上限计入必要资源等待，不计用户在材料确认、曲目选择或保存对话框中的停留，不限制正常音乐播放的持续时间。
  - 预览 / 导出准备提供“取消准备”；音频起播准备中普通播放／暂停显示为“取消起播”并保留已提交位置，“停止”仍取消并归零；有待更新文档时原暂停后换版规则优先。按钮和键盘均能操作，关键提示不随隐藏谱面 / 键盘消失，无预览导出使用宿主可见的进度与取消入口，不强制打开音乐预览。取消某项任务不连带取消无关导出或其他预览的工作。
  - 取消、超时或任务被取代后，其结果不得替换谱面、恢复诊断、继续发声或开始导出写入；提交结果前校验任务、文档、曲目与相关布局 / 播放请求。取消不只是隐藏等待提示；同步计算能否中断、取消响应与临时资源释放须 M0 实测，不能把单纯丢弃 Promise 结果或挂一个计时器当作已解决阻塞。旧计算尚未结束或清理时，不允许连续重试堆积同类重任务，状态须如实说明。
  - 用户主动取消或超时的同版本、同曲目、同类准备，不由自动更新、面板恢复或尺寸变化反复重试；预览通过“重试预览”、音频通过“重试并播放”、导出通过重新执行导出明确发起。因新布局等合法请求替换旧任务时，只拒绝旧任务结果，不阻止新请求按既定规则执行，也不把某类准备取消当成其他能力不可用。硬超限则先缩小材料或降低对应处理成本，不提供无意义的原样重试；新文档版本重新检查软硬限制，不继承旧授权或起播意图。
  - 播放中变速 / 定位的内部重建失败或超时，结束本次续播并进入暂停，不让旧任务迟到发声；同版本保留最后可靠的已提交位置，未成功的定位不算完成。若有待更新文档，按进入暂停后的既定规则应用并归零，再判断新版可用能力。
  - 导出准备取消 / 超时后不得进入保存写入，保存对话框返回后也重新核验任务有效性。开始写入前是准备取消的最后边界；已提交给文件系统的写入不承诺可撤销，需等待并报告真实结果，不能仅因等待较久就声称“已取消且未写文件”，也不自动回滚或重复写入。
- [x] 提示与恢复：性能限制、取消和超时不是 ABC 语法错误，不编造 Problems 行号；能确认是超过预算时才说明预算，未知慢因只说明当前阶段。提供可用下一步与安全的原始详情，不重复弹通知或抢焦点，不因恢复而显示已隐藏提示，不无限自动重试。
- [ ] 性能实现与测量：M0 用正常短练习、大曲集、长单曲、多声部、高密度事件、大量反复、极慢速度和畸形输入，在本地与至少一个 Remote 环境记录耗时、内存与取消响应；据此确定软硬阈值、较慢提示时点、各阶段超时、更新 / 重排防抖与有界任务调度。阈值及可中断实现尚未验证，不将本节产品规则当作性能保证；无法守住边界时记录证据并重新确认方案。

大材料待确认：自动预览已暂停，本次继续可能较慢。  [继续预览]
正常音频等待：正在准备音频…              [取消起播] [停止]
音频等待较久：音频准备较慢，完成后将播放。 [取消起播] [停止]

### 窄窗口与低高度适配

- [x] 窄宽控件：保留直接练习入口，按“播放 / 暂停、停止、隐藏 / 显示提示”“循环、速度、声部”“从此处播放、更多”的稳定分组自然换行，不固定工具栏行数，不增加“练习设置”二级菜单。多曲目选择器独立成行，单曲仍不显示；进度独占一行，低频导出仍在“更多”。尺寸变化不改变命令目标或控件语义。
  - 控件按实际 webview 可用宽度布局，不用挤小字号、琴键或点击区域换取单行；视觉与键盘导航顺序保持一致。曲名 / 路径可省略但须能查看完整文本，键盘与屏幕阅读器也能取得完整名称；关键状态与“暂停后更新并回到开头”等后果不能只剩省略号。较长错误详情可展开，菜单在视口内可滚动，不遮死停止或取消入口。
- [x] 低高度例外：正常三段布局不足以保留可用谱面空间时，改为内容整体纵向滚动。精简控制条至少保留播放 / 暂停、停止，关键状态摘要保持可见；曲目选择、其他分组控件、进度、谱面及展开的键盘均可通过滚动访问，不再把谱面夹在上下固定区域之间。
  - 不自动收起键盘、不切换隐藏提示或音域模式、不写入新的练习偏好；键盘随内容滚动离开视口不等于关闭提示，也不等于 webview 面板隐藏，不触发暂停。用户仍可手动收起键盘或隐藏提示；高度恢复后回到正常布局，尊重用户最后的显隐与展开选择。
  - 整体滚动模式不再给谱面叠加独立的纵向滚动视口；键盘仍可局部横向滚动，必要的谱面横向滚动同样局限于谱面区域，不把页面或工具栏撑宽。播放跟随仍只以谱面位置为目标；用户手动纵向浏览页面或横向浏览谱面后暂停跟随，通过既有“恢复跟随”入口恢复，不被亮键拉回。布局切换本身不恢复已暂停的跟随。
  - 响应式切换不主动提交速度输入、曲目选择或进度拖动，不抢走源码焦点；同一控件保留焦点和编辑状态。必须替换节点或控件几何变化使旧拖动失效时，取消未提交操作并按 §4 恢复合理焦点，不把旧坐标当作新的定位请求。
- [x] 按宽度重排：非播放期间根据最新可用宽度防抖重排谱面；播放期间保持现有谱面排版，工具栏换行与低高度滚动模式仍可响应尺寸变化，谱面放不下时提供局部横向滚动，不持续缩小整张谱来适配。
  - 暂停后应用最后一次宽度；停止或自然结束后同样可适配。只有尺寸变化时保留选曲、练习设置、演奏位置与可靠的查阅选择，不重新准备音频、不自动起播；停止本身的归零语义不变。伴随文档更新时先按 §5 应用最新内容并归零，再对该版本按当前宽度排版，不为旧文本额外重排。
  - 待重排属于布局状态，不冒充“文件已更新”；纯宽度变化不禁用仍然可靠的源码映射，也不解除已有的版本不一致禁用。替换谱面节点时重新关联查阅与播放标记，不复用失效的 DOM / 几何坐标；重排结果须核验文档、曲目与最新布局请求，不能在已开始的新一轮播放中补交旧重排，也不能在关闭后恢复界面。
  - 布局变化尽量保留当前阅读锚点，不改变键盘音域或主动横移键盘，不显示已隐藏的谱面 / 键盘；SVG 导出继续使用独立固定排版，不受此规则影响。
- [ ] 尺寸与重排验证：M0 覆盖宽高充足、窄而高、宽而矮、又窄又矮四类实际面板，记录实际 CSS 可用尺寸、断点、最小可用范围与防抖值；结合中英长文案、VS Code 缩放、多曲目、错误详情和 88 键验证。极小视口的限制须说明，不能靠裁掉停止按钮或自动隐藏提示冒充可用。

### 多曲目文件

- [x] 首版范围：同一 ABC 文档仍共用一个预览，用轻量曲目选择器一次查看 / 播放一首，不连续展示整份曲集、不自动连播、不自动拆文件，也不新增公开命令。学习模板仍推荐一份练习一个文件；多声部不等于多曲目，示范与伴奏可以同属一首。
  - 单曲文件不显示多余选择控件；多曲目时在顶部控制区显示“第 2 / 5 首 · 曲名”，列表同时展示文档顺序、`X:` 和标题，无标题显示“无标题”。序号用于显示与本版本内选择，不充当跨版本身份。
  - 首次创建、关闭重开、重载窗口或重启时默认选文档顺序中的第一首、位置归零，不自动播放；第一首有错误时说明错误，不偷偷跳到下一首。当前选曲仅属于本次预览，临时隐藏 / 同面板重建可保留；本次显式“从光标播放”的曲目与位置优先，不被首次默认值覆盖。
- [x] 手动切曲：打开菜单或取消选择不打断播放；确认另一首时先停音并取消旧起播、定位和音频任务，再切曲并归零，恢复适用设置，不自动准备音频或播放。重复选择当前曲目不视为切换。
  - 进度、停止、整段循环、声音开关与键盘音域只作用于当前曲目，不串联文件内其他曲目；切回之前练习的曲目也从头开始，不保存逐曲暂停位置。谱面选择与播放标记在切换时清除，焦点与隐藏提示遵循既定规则。
  - 播放中有文件更新时，曲目列表与谱面保持当前快照；切曲产生的停音先按 §5 应用最新文档，再核验所选目标是否仍是同一曲目，不套用旧序号。无法确认则提示重新选择，不自动播放另一首；切曲失败不把上一首的谱面当成新曲目，参考谱须明确标注其归属，无该曲目参考谱则显示占位。
- [x] 跨曲源码操作：普通光标移动无论是否播放均不切曲；清除已不适用的查阅标记，但不打断当前音乐或抢占播放跟随。普通播放 / 暂停只控制当前曲目，不使用光标暗中换曲。
  - 显式“从光标播放”可在可靠确定当前文档的曲目和音符后，停掉旧曲、切换并按所请求位置起播；保留源码焦点，按需显示预览，仍遵循音频准备、取消与单窗口互斥。公共头部、曲间空白或无可靠音符映射时提示，不猜测相邻曲目、不从头播放；“从所选音符播放”仅使用当前预览曲目的有效选择。
  - 已有播放快照待更新时，不绕过禁用的源码起播；先暂停应用最新文档后再显式发起请求。请求绑定文档版本、曲目与位置；准备期间变化或取消后不得改播其他曲目。
- [x] 更新与身份：同一预览应用新版本时，可靠识别原曲目则保留选曲并按既定更新规则归零；原曲目被删除或不能可靠对应时进入“请重新选择曲目”，不按旧序号、同名标题或重复 `X:` 自动换曲。暂时空白 / 解析失败沿用空状态和旧谱规则，不把暂时失败当作删除所有曲目设置。
  - 当前版本内明确选曲与跨版本恢复身份是两回事：可明确选择的曲目不因无法持久识别而一律禁用，但不继承身份不可靠的历史音乐设置。速度、循环、声部与自动伴奏按曲目隔离，界面偏好按文件共用，详见 §5。
- [ ] 曲目解析与映射验证：继承文件公共头部和适用指令，曲内相对范围须正确还原为整个源文件的位置；验证缺失 / 重复 `X:`、同名、增删、重排、改标识、局部错误及分界不可靠场景。单曲有错且其他曲目边界可靠时不封禁整个曲集；文档级结构不可靠时明确限制相关能力，不默默跳过错误曲目或只取第一首。可靠身份规则与存储键由 M0 验证，不仅凭标题或数组下标推断。

### MIDI / SVG 导出

- [x] 导出版本：使用执行命令时目标文档的当前内容快照，包括未保存修改；有可用编辑器文档时以该文档为准，否则读取对应文件，不用磁盘旧版覆盖缓冲区，也不把预览缓存当来源。未保存新文档同样可导出，不要求先保存 ABC。
  - 来源按 §2 锁定；从预览发起时使用其绑定文档，不能跟随另存为后变为活动状态的其他文件。预览 / 播放版本落后时明确提示“导出当前文档，非正在播放 / 显示的版本”，未保存内容标明“包含未保存修改”。首版不提供导出旧快照的选项。
  - 导出范围：单曲文件直接准备；多曲目每次先从当前文档快照的列表确认一首，显示序号、`X:` 和标题。可预选可靠对应的预览当前曲目或调用时源码光标所属曲目，仍须确认；无可靠预选则不代替用户选择。取消无副作用，选择只用于本次导出，不改变预览选曲或播放，不提供整集拼接 / 批量导出。
  - 任务绑定文档身份、内容版本、已确认曲目范围和格式；曲目选择期间、准备期间及保存对话框返回后、开始写入前再次校验。已发现内容变化、身份迁移或来源不可用时取消本次写入，提示重新导出，不自动改用新版或无限重试；从预览发起的任务在该面板关闭后也取消。仅切换焦点不改变导出目标。
- [x] 独立准备与播放隔离：没有预览也可导出，不要求创建 / 显示音乐预览、加载音色或先播放；已有有效同版本数据可在不污染播放器状态的前提下复用。
  - 导出不主动暂停、定位、换版、展开提示或接替其他预览的音乐；不会解除旧谱与新源码之间的联动禁用。原生界面操作若导致面板隐藏，仍按 §5 暂停；取消 / 完成导出均不自动续播。
  - 只生成该格式必要的数据，不把 MIDI 数据生成等同于音频采样合成。导出任务不写回播放器的速度、声部设置、待更新状态或持久记录；渲染 / 音频 / 导出能力分别判断，音频准备失败不直接禁止导出。
- [x] MIDI 仅按 ABC 材料：不应用播放器速度百分比、声部静音覆盖、自动和弦伴奏开关、临时节拍器、当前位置或整段循环；不提供“按当前练习设置”模式。界面说明“按 ABC 原速度与声部导出，不含播放器练习设置”。
  - 保留 ABC 本身受支持的速度（含曲中变速）、反复、记谱声部及伴奏 / MIDI 指令；自动伴奏采用由材料及明确的导出默认配置确定的行为，不借用历史播放器开关。支持范围与缺省行为需验证，不承诺 abcjs 未支持的指令。
  - 导出所确认曲目的完整有限演奏序列，不包含其他曲目，不从当前播放位置截取，不展开播放器无限循环。MIDI 是音乐事件数据，不含本地钢琴音色录音，不承诺在其他播放器中听到完全相同的音色。
- [x] SVG 外观：白色背景、黑色谱面，包含乐谱标题和记谱内容，不包含工具栏、键盘、播放光标、查阅选择或源码联动高亮。隐藏提示不影响完整谱面的导出，也不改变界面的提示显隐。
  - 使用独立且稳定的导出排版基准，不受预览主题、窗口宽度、滚动或缩放状态影响；长谱不能只导出可视部分或第一个 SVG 片段。固定布局参数、ABC 排版指令兼容范围及多片段合并方案待验证。
  - 输出需能脱离 VS Code 正常显示，不依赖 `--vscode-*`、webview 样式或临时资源地址；不携带脚本、事件处理器和不必要的本地路径信息，外部资源与字体策略需在实现中校验。
- [x] 保存流程：沿用两个导出命令与预览“更多”入口，不新增公开命令。准备有效数据后使用 VS Code 原生保存对话框；已保存文档默认使用源文件基本名加 `.mid` / `.svg`，未保存文档参考有效曲名，无曲名用 `Untitled`；多曲目在建议基本名后附加本次所选曲目的序号与可用曲名，避免不同曲目默认重名。名称清理后仅作可修改建议，序号不作为设置身份。
  - 用户确认目标路径与覆盖；取消不写文件，不保存 ABC、不改变预览绑定或练习设置。不得以导出覆盖来源 ABC，目标写入失败明确提示，仅在写入成功后报告成功；不自动打开导出文件或启动外部播放器。用户明确保存的导出文件可产生 git 改动，与本地练习设置不写项目文件的规则区分。
  - 内容不能生成目标格式时说明原因，不导出旧参考谱；空白内容不生成空壳文件，合法全休止符不视为空白，普通告警不一律阻止导出。写入权限 / 路径错误不标成 ABC 行错误；无预览时也提供可见的进度、取消与失败反馈，不因此打开音乐预览。
  - 导出准备遵循本节分阶段上限与取消规则，音频超限不直接禁止按格式独立导出；等待用户选择不算计算超时。准备取消 / 超时与已经提交的文件写入分开，后者不承诺撤销或自动回滚，须报告真实结果。
- [ ] 导出实现与验证：M0 验证无预览、无音频准备的独立生成路径，以及与播放快照隔离；若宿主限制阻碍，记录证据并回到设计确认，不静默改成强制打开预览。M1 验证格式完整性、保存取消 / 覆盖、写入前版本检查、错误分类与独立查看效果。多曲目每次确认一首，验证选曲与预览隔离、公共头部继承及输出范围完整，不默默只输出第一首；批量导出不在本轮范围。

## 4. 键盘、焦点与无障碍（首次开发最易忽略）

- [x] 默认组合键策略：第一版提供可从命令面板发现、可自行绑定的核心命令，不新增工作台级默认快捷键组合；保留预览局部空格与控件标准键盘操作。
  - 首版公开八个基础命令，显示名称、ID 与目标规则见 §2；不提供窗口级停止、隐藏提示或循环切换的公开命令，后两项保留预览控件与标准键盘操作。
  - 命令必须明确目标文件或预览，不因最近使用过其他文件而误控其音乐；不接管 VS Code 的命令面板、编辑器组切换、关闭标签页等原有操作。
- [x] 局部空格：焦点在谱面或预览背景时切换播放 / 暂停；起播准备中再次按下取消起播并保留已提交位置，内部缓冲中按下则暂停并取消续播，有待更新文档仍按暂停规则应用并归零。源码、学习记录、其他视图及外部 agent 的空格不控制音乐。
  - 按钮、开关、输入框、菜单等保留自身按键语义，不同时触发播放；不拦截输入法组合输入或带修饰键的组合键。
  - 长按只触发一次。空格与播放 / 暂停按钮共用状态规则，包括待更新时暂停会应用新版本并重置位置；不可播放状态下不会绕过禁用条件。
- [x] 点击谱面的焦点：定位对应源码，但焦点留在预览；显式“转到源码编辑”操作才转移焦点。若源码未显示，在其他编辑器组显示，不把当前预览替换成后台标签；版本不一致时禁用旧位置映射。
- [x] 焦点进入与恢复原则：主动“打开音乐预览”进入预览，首次优先聚焦可用的播放按钮，未就绪时聚焦预览容器；从源码执行播放或从光标播放时保留源码焦点，包括按需创建 / 显示预览。
  - 文件自动更新、音频加载完成、播放高亮均不抢焦点；加载完成后不把用户从当前输入处拉回播放按钮。
  - 隐藏提示或重建移除了当前聚焦元素时，在焦点仍属于预览的前提下恢复到合理的现存控件或容器；若用户已转到源码或其他区域，不抢回来。
  - 窄宽 / 低高度切换遵循 §3，视觉与 Tab 顺序一致；尺寸变化不提交未确认输入或误触发播放。菜单可用键盘滚动，聚焦项不被驻留控制条遮住，关闭菜单后按既定规则返回触发控件。
- [x] Tab 与控件按键原则：Tab / Shift+Tab 按界面顺序导航，不创建循环焦点陷阱；谱面与键盘滚动区可用键盘访问，但不把每个音符或 88 个琴键加入 Tab 顺序。逐音查阅可通过原生源码编辑器完成。
  - 方向键遵守当前控件语义：进度条调整进度、菜单选择选项、滚动区浏览，不全局解释为快进。按钮的 Enter / 空格按控件语义激活。
  - Esc 关闭当前菜单或取消未提交编辑，不暂停、不停止、不关闭预览；通过 Esc 或菜单内关闭操作退出时回到触发按钮，主动点击其他控件或显式导航则遵从用户指定的焦点目标。
  - 保留 VS Code 原有的离开 webview 途径与显式转到源码操作；M0 用无鼠标流程验证能进入、操作和离开，不能仅凭 DOM 设计认定无焦点陷阱。
- [ ] 无障碍实现与验证：具体 Tab 顺序、ARIA、谱面 SVG 与琴键的可访问描述、焦点可见性及高对比度；播放状态和错误适度播报，不逐音 / 逐帧通知屏幕阅读器。
- [ ] 按键与焦点细节：将 §2 的命令目标规则落实为上下文键与 `when` / `enablement` 条件；输入提交 / 取消交互、进度键盘步长与提交时机、焦点恢复目标仍待细化。M0 验证实际跨编辑器组显示、命令面板上下文、播放按需打开、webview 按键传递和重建行为。

## 5. 平台约束与生命周期

- [ ] Webview 通信协议：消息类型、版本兼容、状态恢复（隐藏后被销毁重建）
- [ ] CSP 与资源：nonce、`asWebviewUri`、音色路径；具体白名单与消息校验按 §7 的安全边界落实，不放行远程域。
- [x] ★ 音频生命周期：继续当前版本、暂停后更新；失焦继续、隐藏暂停；新播放接替旧播放。
  - 起播与释放：只有用户明确的播放操作可发声；打开文件、恢复界面、内容更新不自动起播。起播准备中再次普通播放／暂停取消请求并保留最后已提交位置，停止则取消并归零；有待更新文档时按暂停规则应用。关闭预览必须停止其音频并释放资源，已取消 / 已关闭的异步加载任务不得随后发声或覆盖更新的显式请求；加载失败明确提示。
  - 文件身份与可用性：可靠的首次保存 / 重命名迁移先暂停并取消待起播，再校验新来源；来源确认不可用且无可用缓冲区时立即停音、取消请求并保留状态页，不继续旧播放快照。普通内容修改仍按下方延后更新规则处理，不能把两类事件混为一谈；另存为不转移原预览，细则见 §6。
  - 变速 / 定位的内部重建：已在播放中的操作可在短暂缓冲后继续当前播放，不视为用户暂停，不触发待更新文档换版，仍绑定当前播放快照。若期间用户暂停 / 停止、面板隐藏 / 关闭或被其他预览接替，则取消后续续播；不得让旧异步任务恢复发声。内部准备失败或超时则取消续播并进入暂停，按 §3 保留最后可靠位置或应用待更新文档，不把已经超时的缓冲当作仍在播放。声部调整需要的显式暂停仍按下述规则应用文档更新。
  - 播放中文件变化：保持当前音频与谱面版本一致，标记“文件已更新，暂停后应用”。从发现内容变化起，暂时禁用源码 ↔ 旧谱面的定位与基于源码的起播，清除源码播放高亮；旧谱面和键盘内部的播放高亮继续。
  - 应用更新：在暂停、停止或自然播放结束后应用最新内容，重置播放位置到开头，不自动起播；循环回到开头不视为自然结束。暂停入口提示“暂停后更新并重置位置”。没有内容变化的普通暂停保留位置；非播放期间按文档变化自动更新，仍受 §3 的软阈值确认及主动取消 / 超时规则约束。
  - 更新失败按能力处理：最新内容渲染失败时保留明确标为旧版本的参考谱，禁用旧谱播放及源码映射；最新谱面渲染成功但音频准备失败时，保留当前谱面及其可靠源码定位，仅限制依赖音频的能力。不得因音频失败改回旧谱或用旧偏移定位新文档；普通解析告警不一律禁止播放。主要状态与重试操作见 §3。
  - 失焦与隐藏：点击源码、对话或外部 agent 窗口不因失焦主动暂停；预览成为后台标签等面板隐藏情况会暂停。仅隐藏谱面 / 键盘提示不暂停音乐。尺寸变化、低高度整体滚动以及键盘滚出视口不是面板隐藏，不暂停音乐；宽度引起的重排按 §3 延后至非播放期间，纯布局变化不重置演奏位置。
  - 临时隐藏后恢复：在同一面板生命周期内保留练习设置，内容版本未变时恢复暂停位置，有待更新版本则按上述规则更新并重置位置；重新显示不自动发声。隐藏触发的暂停与被其他预览接替触发的暂停同样应用待更新规则。关闭后重开或重启不属于临时隐藏，按下方规则恢复练习设置但播放位置归零。
  - 多预览协调：同一 VS Code 窗口内只允许一个预览发声；启动 B 前先暂停 A，再播放 B。单纯打开 / 查看 B 不触发接替；若该操作使 A 隐藏，则仍按隐藏规则暂停 A。不控制其他应用或其他 VS Code 窗口的音频。
- [ ] 生命周期实现验证：M0 验证隐藏时状态保存与停止发声、内容重建、播放接替的互斥及异步取消；不将后台常驻播放作为第一版功能。
- [x] 性能产品规则：大材料采用软提示与硬上限，准备较慢时提示、超时取消，按阶段降级、不截断材料；自动更新受确认与取消状态约束，详见 §3。
- [ ] 性能实现验证：软硬阈值与阶段时限、防抖、按需音色加载、内存上界、同步重计算的可中断性、任务结果校验与取消后释放资源由 M0 实测，不能只靠 UI 计时器宣称不会阻塞。
- [x] 设置模型：按工作区与完整文档标识保存本地记录；提示显隐、键盘展开 / 音域模式按文件共用，速度、循环、声部静音和自动和弦伴奏开关在文件内进一步按可靠曲目身份隔离。关闭重开选第一首并仅恢复其适用音乐设置，与本次预览的选曲和临时播放状态分开，明细见下表。
- [x] 播放位置恢复范围：临时隐藏 / 同一面板生命周期内的内容重建保留同版本暂停位置；关闭后重开、重载窗口或重启时，恢复的默认起点为开头，不持久保存播放位置，也不恢复正在播放或等待起播的请求。本规则限制旧状态恢复，不覆盖用户本次新发起的“从光标 / 所选音符播放”的曲目与位置目标。
- [x] 声部恢复：先可靠识别为同一曲目，再比较有序声部清单（标识、显示名称及顺序），未变才恢复静音覆盖；声部增删、改名、改标识、重排或无法确认时，清除该曲目的旧静音覆盖，回到乐谱 / 初始播放配置，并提示“声部已变化，请重新检查发声设置”。不同曲目即使共用 `V:1` 等标识也不继承静音。
  - 不按“第几个声部”或显示名猜测身份，也不部分继承仍能匹配的声部。同曲身份已确认时，速度、循环与自动和弦伴奏开关不因声部结构变化重置；其他曲目的记录和文件级界面偏好不受影响。曲目身份本身不可靠时，不应用其历史音乐设置，使用默认值并提示，不擦除其他曲目的记录。
  - 只在有效新版本正式应用时比较声部结构，不提前修改仍在播放的快照。暂时空白或解析失败不自动用空声部清单覆盖旧记录；恢复有效内容后再判断。
- [ ] 状态存储实现细节：文件级 / 曲目级记录结构与校验、可靠曲目与声部标识来源、单曲转多曲的记录关联、首次保存 / 重命名识别与 §6 目标优先冲突规则的落地；不按文件名猜测关联，M0 验证基本保存、恢复与迁移路径。无工作区 / 跨工作区记忆范围及记录清理 / 多窗口冲突的用户可见策略是待决策 P04、P05，不仅是底层存储技术选择。
- [x] workspace trust：受限模式完整支持、不降级，无功能降级清单；约束与未来设置的登记要求见 §7。

### 状态维度与事件转换（已确认行为的文档规范）

本节整理已确认规则，不是实现枚举、消息协议或运行验证结果；不枚举各维度的全部组合，也不为 §9 的待决策项补造默认值。用户可见能力表见 §3。

| 独立维度 | 需要表达的信息 | 不能混同的情况 |
| --- | --- | --- |
| 来源与版本 | 可用 / 不可用 / 迁移后旧绑定终止；文档身份、最新内容、显示 / 播放快照、曲目及待更新标志 | 来源失效不同于播放中的普通修改；曲目序号不是跨版本身份 |
| 谱面能力 | 空内容、准备、软阈值待确认、当前有效谱面、旧版参考，以及失败 / 超限 / 取消 / 超时原因 | 音频失败不使有效谱面失效；纯重排失败不等于文档换版 |
| 音频与传输 | 未准备、起播准备、播放、内部缓冲、暂停、自然结束；可复用资源及其版本 / 设置适用性 | 资源准备好不等于正在发声；自然结束后的默认位置和再次播放仍待 P01 |
| 操作请求 | 起播 / 续播意图、文档与曲目目标、未提交定位、有效 / 取消 / 被替代状态 | 查阅位置、定位候选与已提交播放位置分开；旧请求不能接管新请求 |
| 面板与界面 | 可见 / 隐藏 / 关闭；焦点、提示显隐、键盘展开、跟随与布局请求 | 失焦、内容滚出视口、隐藏提示均不等于面板隐藏 |
| 独立导出 | 选曲、准备、等待保存选择、写入、成功 / 失败 / 取消；来源快照、格式与目标 | 导出不依赖音频就绪；准备可取消不等于已提交写入可撤销 |

**统一约束**：
- 下表中的“应用更新”统一指：到既定换版时机核验最新来源与曲目，归零并按 §3 进入有效谱面、空状态、待确认、旧版参考或错误状态；不承诺所有新内容都能成功渲染，不自动准备音频或起播。
- 每次提交异步结果前核验所属请求、绑定、文档、曲目和相关布局 / 播放上下文；取消、超时、关闭或已被替代的结果不得复活旧状态、声音、诊断、设置写入或尚未开始的导出写入。已经提交的导出写入按真实结果结束。
- 事件按实际发生顺序改变当前状态，不把“取消优先”解释为永久压制之后的新显式请求；停止后迟到的旧定位不能移动位置，新请求的结果也不能被旧取消回调清掉。
- 普通内容更新在播放及其内部缓冲期间保留当前快照；来源确认失效、身份迁移和用户暂停是独立中断条件，不借布局变化提前换版。
- 主动取消 / 超时后的同版本、同曲目、同类准备须明确重试；合法新布局等请求替代旧任务不触发该禁用，不连带禁用其他能力。调度、真正中断计算与资源释放仍须 M0 验证。
- 表中的可用操作仍受 §2 目标校验、§3 能力 / 软硬限制及 §6 来源规则约束；未知转换登记到 §9，不据库的偶然行为默认为产品规则。

| 保存选择确认 | 对话框返回，任务 / 来源再次核验通过，目标不是来源 ABC | 开始写入用户确认的路径；不保存 ABC 或改变预览绑定 | 不自动续播 | 开始写入前仍可阻止失效任务 | 查看保存进度，不承诺已提交写入可撤销 |
| 已提交写入完成 / 失败 | 文件系统返回真实结果 | 仅据真实结果报告成功 / 失败；不自动打开文件 | 不发声 | 不用取消回调假称未写入，不自动回滚或重写 | 查看结果；失败后可显式重新导出 |

### 练习设置与临时状态

以下持久恢复规则以“记住每个文件的练习设置”开启为前提，适用于已保存文档；没有可用记录时使用默认值。未保存新文档仅保留会话内设置，首次保存后可靠关联才进入持久保存流程（见 §6）。恢复设置本身不准备音频、不起播，也不新建已经关闭的预览。

| 内容 | 关闭预览 / 重启后的处理 | 首次使用 / 无可用记录 |
| --- | --- | --- |
| 速度百分比 | 按可靠曲目身份恢复已提交百分比，不保存旧 BPM 作为新曲速度 | 100% |
| 整段循环 | 按可靠曲目身份恢复，只循环该曲目，仍需手动播放 | 关闭 |
| 记谱声部静音覆盖 | 同曲身份可靠且声部清单未变才恢复，不跨曲复用 | 不额外静音，遵循该曲目初始播放配置 |
| 自动和弦伴奏开关 | 按可靠曲目身份独立恢复，不套用记谱声部编号 | 无用户覆盖，遵循该曲目初始播放配置 |
| 谱面与键盘提示显隐 | 按文件共用；隐藏时明确显示“提示已隐藏”和“显示提示”入口 | 显示 |
| 键盘展开 / 收起、音域模式 | 按文件共用；模式为乐曲或完整 88 键，实际音域按当前曲目重新计算 | 展开，乐曲音域 |
| 当前选曲 | 仅同一次预览中保留，不持久恢复；新显式跨曲起播优先于默认选择 | 文档第一首 |
| 播放位置 | 不持久保存，重开及手动切曲归零；临时隐藏保留同曲同版本位置 | 当前曲目开头 |
| 正在播放、等待起播、选中音符、打开的菜单、未提交输入 | 不恢复旧操作，不持久保存 | 无待执行操作 |

- 使用 VS Code 扩展的工作区状态保存必要的文件 / 曲目 / 声部标识和轻量设置，不写 ABC、学习档案或额外项目配置文件；播放器操作不产生项目 git 改动。不自动跨设备同步，也不要求跨窗口实时同步。
- 不为状态恢复持久保存 ABC 全文、合成音频或播放位置历史。外部文件系统 agent 不能据此获知播放器当前设置；需要进入学习记录的信息仍由用户 / agent 显式记录。
- 只保存已提交设置；过期或已取消预览任务不得覆盖更新后的记录。无效记录安全回退，不恢复失效的源码范围或音符选择。可靠迁移遇到目标已有面板或记录时按 §6 目标优先规则处理，来源记录不覆盖或混入目标，也不因本次冲突自动删除。
- 最小配置项为 `abcdesk.rememberPracticeSettings`，布尔值，默认 `true`，可通过 VS Code 用户 / 工作区设置调整。关闭时不从历史记录恢复或继续持久保存，但不立即改动当前预览的练习设置、不打断播放；重新开启不把旧记录强行覆盖到当前界面。
- 预览“更多”提供“重置本文件练习设置”，先暂停或取消待起播请求，再允许操作：恢复该文件共用的界面默认值，并清除该文件所有曲目的音乐设置覆盖；入口说明作用于本文件全部曲目，不修改 ABC 或学习记录，不自动起播，不新增公开命令。重置设置不代替停止或切曲操作；无内容更新时保留当前选曲和暂停位置，暂停应用了新版本则按既定规则归零并核验曲目。

## 6. 文件协作与外部 agent

- [x] AI 职责边界：插件不集成 AI 对话；对话由能访问文件系统的任意外部 agent 提供，不要求其运行在 VS Code 内，不绑定具体产品，不提供命令唤起特定 chat 的集成。
  - 文件是基础协作接口；用户向 agent 指出说明与当前练习路径，并在外部环境授权读写。存在说明文件不代表 agent 会自动读取或获得权限。
  - LM tools 等工具接口仅为后置增强，不承载对话，也不成为基础文件工作流的依赖。
- [x] ★ 文件协议与工作区资产：采用可选轻量模板，参考结构与最小内容见产品计划 §3。
  - 工作区共享 `learning-guide.md` 与 `profile.md`；每个练习目录保存 `exercise.abc` 与 `session.md`。
  - `session.md` 顶部保留当前进展与下次继续事项，下方按次追加反馈、调整理由及撤除提示后的自述结果；修改同一练习时保持 ABC 路径稳定。
  - 模板由用户和外部 agent 维护；目录与文件名不是插件硬编码要求。第一版不要求项目清单，不解析或自动写回学习档案，独立 ABC 不依赖这些文件。
- [x] 外部文件协作边界：普通文件系统 agent 不能假设读到未保存的编辑器内容；交给 agent 修改前先保存，避免同时写同一文件。冲突沿用 VS Code 原生处理，插件不静默覆盖或替用户保存。
- [ ] 生成手感细节：非播放期间按 §3 的分级保护与取消规则自动更新，超软阈值需确认，同版本同曲目的预览已主动取消 / 超时后不反复自动处理；播放期间提示待更新，暂停后应用（见 §5），均不自动起播；未打开或已关闭时不因 AI 写文件弹出。防抖阈值与错误文案后续细化；M0 验证真实外部磁盘写入、版本不一致时禁用源码联动，以及生成中暂时不可用内容的提示。
- [x] 诚实性边界：无演奏输入时，AI 只依据自述辅导，界面与文案不得暗示"已听到演奏"；模板区分用户自述与 AI 建议，不将建议记成已验证能力。
- [ ] 诚实性落实验证：在 M2 模板、记录示例与用户旅程中检查上述区分；原则已确认不表示模板已制作或学习效果已验证。
- [ ] 练习库元数据：注释行约定（`level`、`tags`）与检索体验（后置 P1）
- [ ] 会话生命周期细节：按练习目录积累记录的原则已定；创建入口、命名建议与归档细节后续按需要确认。

### 文档身份与文件操作

- [x] 未保存新文档：语言模式为 ABC 即可主动预览、播放与联动，不强制先保存；多个未保存文档分别绑定，不按标签名或相同内容合并。明确显示“尚未保存；与外部 agent 协作前请先保存”，不反复弹通知。
  - 练习设置仅保留在当前会话，不将临时文档标识写入持久记录；重启不承诺恢复这些设置，原生未保存内容恢复由 VS Code 管理。已有文件的未保存修改仍正常预览，不受此限制。
  - 保存、另存为、放弃未保存内容均使用 VS Code 原生操作与确认；插件不代为保存，不缓存全文作为文档备份。取消保存或取消关闭不破坏原预览；真正放弃且来源文档不可用时进入下述来源不可用状态。
- [x] 首次保存与重命名：能可靠确认原文档与目标的对应关系时，首次保存、重命名 / 移动视为同一练习；目标无冲突时接续原预览并更新来源标识与显示路径，当前练习设置随之接续，持久记录迁移仍受记忆开关约束。目标已有面板或设置时采用下方目标优先规则，已有文件另存为仍按独立文件处理。
  - 身份切换先暂停并取消待起播、旧异步任务与未提交定位；重新核验目标内容和映射。同一面板且内容未变可保留暂停位置，有内容变化则应用新版本并归零；声部静音仍需结构校验，不自动续播、不抢焦点、不新建已关闭预览。
  - 只有可靠的操作关系才能迁移，不能只凭先关闭后打开、同名、相同正文或相邻文件事件推断。VS Code 内操作与外部 agent / 文件管理器操作的可识别程度需 M0 实测；无法确认时不自动改绑或迁移，原来源不可用则显示状态，用户可主动预览新文件。
- [x] 可靠迁移的目标冲突：目标已有预览或设置记录时，目标已有状态优先；暂停受迁移影响的预览并取消旧请求，不自动续播或抢焦点。目标已有面板继续作为唯一可播放预览，重新核验实际文档与曲目；同版本保留可靠暂停位置，内容更新按原规则归零。
  - 目标已有设置仍须按记忆开关、曲目与声部规则校验；无效记录回退默认值，不用来源记录填补或混合。目标面板存在但没有适用记录时，同样不导入来源设置。来源记录不因冲突自动删除，记录清理与跨工作区范围另见 §9 P04、P05。
  - 来源面板若存在，保留为“文件已迁移”的只读状态页；可保留明确标为参考的旧谱，不再作为第二个可播放预览，不执行旧绑定的播放、定位、设置修改或导出。仅提供明确的目标预览入口，不自动关闭来源页、打开目标页或恢复任何旧请求。
  - 只有目标设置、没有目标面板时，不自动创建目标面板；用户通过来源状态页的“打开目标预览”显式进入，已有面板则显示“转到目标预览”并复用。入口重新核验目标，不存在时说明原因、不回退旧路径；不增加公开命令。原本没有来源面板时也不创建状态页。
  - 来源页的旧请求与后续回调不能修改目标状态或记录；尚未提交的旧来源导出不得写入，已提交写入仍报告真实结果。没有可靠迁移关系时不套用目标优先规则猜测绑定；无冲突的可靠迁移仍按上项接续。
- [x] 已有文件另存为：视作另一份练习，原预览继续绑定原文件，不追随另存为后自动变为活动状态的新源码；新文件须主动打开 / 播放才创建或复用它自己的预览。
  - 原设置不复制到新路径；新目标已有记录时遵循自己的设置与声部校验，无记录时用默认值。首次保存未保存新文档不属于此类复制操作。
  - 原文件的内容仍以其当前有效文档 / 磁盘为准，不把新路径缓冲区当作旧来源；若原内容因此变化，沿用待更新规则。仅关闭源码标签不关闭预览；原文件可读取时仍能单独练习。
- [x] 来源确认不可用：原文件被删除 / 无法读取且没有可用编辑器缓冲区时，保留已有预览页，显示来源状态与原路径；立即停音、取消起播和过期任务，清除播放标记与旧源码联动。最后成功谱面仅供参考，无谱面则占位，不允许播放或把它作为最新版本导出。
  - 此状态不同于播放中的普通内容更新，不等曲子结束才停音。状态不随“隐藏提示”消失，也不强行显示已隐藏谱面；不自动关闭、重建原文件、搜索替代文件或改绑新路径，用户仍可自行关闭预览。
  - VS Code 仍保留可用的对应编辑器缓冲区时，继续按该文档预览并提示磁盘状态；保留未保存修改，冲突沿用原生处理。插件缓存的旧正文不算可用缓冲区；不能因一次删除事件就丢弃用户编辑。
  - 原路径重新可读时，已有预览重新获取并校验当前内容，应用后默认位置归零，不恢复旧起播或旧映射；有效声部仍按 §5 校验。重新可读本身不播放、不抢焦点，也不复活用户已关闭的预览。
- [ ] 文件事件实现与验证：首次保存关联、重命名（含目录移动）、另存为后的原文档来源、关闭 / 放弃缓冲区、外部原子替换、读取失败与恢复、目标冲突及异步事件乱序。短暂删除再创建须合并核验，不能仅凭单次通知认定永久丢失；确认来源不可用后及时停音，具体防抖与判定策略由 M0 验证。

## 7. 隐私、安全与合规

- [x] 受限模式（Workspace Trust）：声明支持不受信任工作区，完整支持、不降级。ABC 内容只作为记谱数据解析，不执行工作区代码，不读取工作区提供的路径、外部程序、URL 或脚本类设置；预览、播放、联动、导出与练习设置记忆在受限与信任模式下行为一致，不弹出信任请求。
  - 首版唯一设置 `abcdesk.rememberPracticeSettings` 为布尔值，可从工作区设置读取。未来若新增可能指向路径、外部程序、URL 或自定义模板的设置，必须登记为受限配置（受限模式只读用户级值）或重新确认本声明，不能静默扩大信任面。
  - 受限模式下写入仍只经用户确认的原生保存对话框，不自动创建或修改工作区文件；工作区状态记录仅含文件 / 曲目 / 声部标识与轻量设置。
- [x] 不受信任内容：来自文件的标题、声部名、告警文案与路径在 webview 中一律按文本渲染，不拼接为 HTML。webview 启用 CSP，只允许带 nonce 的自有脚本和扩展自有资源，不放行远程脚本或远程资源；ABC 排版 / MIDI 指令不得触发资源加载或脚本执行。扩展侧不信任 webview 发来的消息，按类型、范围与当前文档版本校验，不接受其中携带的任意路径。
  - 超大或畸形文件按 §3 的软硬限制与分阶段超时处理，不提供绕过安全上限的入口，信任与受限模式一致；不把资源限制当语法错误，不自动截断材料。防止冻结编辑器与可取消计算需 M0 实测，具体阈值尚未锁定。导出的 SVG 不携带脚本与不必要的本地信息（见 §3）。
- [x] Remote 与 Web：本地优先、Remote 兼容。扩展侧不依赖本机路径与 Node `fs`，读取文件使用 VS Code 文档与 `workspace.fs` API，不假设 webview 与扩展侧共享文件系统；音色与 webview 资源仅经 `asWebviewUri` 加载。音频与键盘可视化只在本机 webview 完成，不在远端处理音频。
  - M0 至少在 WSL 或 SSH 之一冒烟：打开、预览、播放、外部写入后更新、导出保存到远端工作区，并记录音色加载时长与失败表现。vscode.dev / web 扩展不承诺，不提供 browser 入口，但核心代码避免 Node 专用依赖，不主动堵死。虚拟工作区（如 GitHub Repositories）不作为首版目标，也不主动禁用；无法读取或保存时按 §6 来源不可用与 §3 导出失败规则提示，M0 记录实际行为。
  - 未保存文档、导出与保存对话框在 Remote 下遵循同一规则，保存目标由原生对话框决定，插件不猜测本机 / 远端路径。
- [x] 网络与遥测：首版不发起任何网络请求，不收集遥测，不上传 ABC、学习记录或播放器状态；仅内置钢琴音色。`%%MIDI program` 等其他乐器指令播放时统一使用钢琴音色，并在状态 / 声部说明中标明“首版仅钢琴音色”；MIDI 导出是数据，仍保留 ABC 材料中的乐器指令，不受播放音色限制。
  - CSP 不放行远程域，abcjs 默认的远程音色地址不得被触发，现有强制钢琴音色的路线需在移植中保留并验证。未来若引入远程音色库、API 或云功能，作为独立决策处理：显式开关、默认关闭、隐私说明与失败回退缺一不可。
  - 对外说明只需一句：“ABC Desk 完全离线运行，不发送任何数据。”隐私文件与商店合规文本后置到 M4，但零网络基线从第一天遵守。
