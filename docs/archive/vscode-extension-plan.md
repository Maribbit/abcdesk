# ABC Desk for VS Code 产品计划（v0.2 草案）

**状态**：D0 收口中（2026-09-26）。v0.2 保留学习反馈进第一版、上架后置与质量基线；本轮整理状态转换、用户旅程和剩余事项，核心产品行为仍有待决策项，尚未开始扩展实现或完成运行验证。
**工作名**：ABC Desk，面向练习的 ABC 音乐工作台；命令分组为 `ABC Desk`，内部命令 ID 前缀为 `abcdesk.`。原浏览器项目仍称 ChatMusic；新工作名不代表已核验 Marketplace、仓库名称或商标可用性，publisher 与商店身份后置。
**关联文档**：[交互设计清单](./vscode-extension-design.md)（D0 工作文档）、[方向评估](./vscode-extension-assessment.md)（历史评估，不作修改）

## 1. 定位与目标分层

借助具备文件系统访问能力的外部 AI agent、ABC 与可交互的音乐预览，完成"明确目标 → 小型示范 → 自己尝试 → 反馈 → 针对性调整"的即兴学习循环。插件不集成 AI 对话，不要求 agent 运行在 VS Code 内。

| 层级 | 内容 | 优先级 |
| --- | --- | --- |
| L1 学习实验 | 验证"AI 辅助即兴学习循环"是否成立（首要验证目标） | 最高 |
| L2 优质 ABC 工作台 | 可独立存在的优质工具（预览、播放、键盘、联动、诊断、导出），保底交付物 | 高（= M1） |
| L3 上架 | VS Code Marketplace 发布，后置选项，不阻塞实验 | 后置 |

**质量基线（从第一天执行，后补昂贵）**：主题变量（`--vscode-*`）与高对比度、webview 生命周期与状态恢复、消息协议、音频与资源释放、无障碍基础、文案抽取与自有 UI 中英同步维护、命令命名一致性、激活性能、本地音色合规。

**后置（验证学习价值前不做）**：publisher 与发布流程、商店资产及其翻译、完整双语文档与其他语言、TreeView 管理 UI、LM tools 集成、复杂选区循环、Markdown 内 abc 块。自有 UI 英文默认 + 简体中文属于首版范围，不再笼统后置全部翻译。

**诚实性边界**：无演奏输入时，AI 只依据用户自述辅导，不得声称"听到了"或客观评定了演奏。

## 2. 背景与目标

- 现状卡点：ChatMusic 只活在浏览器里；ABC 产出需要手动拷贝，无法用文件与版本管理承载练习积累。
- VS Code 提供：文件编辑、git、音乐预览宿主、终端 / Tasks（未来反馈路线的运行环境）；对话由外部 agent 提供，可位于编辑器内或编辑器外。
- 市场位置（2026-09 调研）：ABC 类 VS Code 插件品类活跃度极低（头部停更 / 归档，总安装量不足一万），且没有任何插件同时具备钢琴键盘可视化、完整播放控制与双向联动。
- 学习流程前提（需实测，尽早验证）：实际使用的外部 agent 支持并获准修改音乐文件、读取学习档案。文件约定是数据组织方式，不会自动带来读写权限；不可用时明确调整授权 / 使用环境，或由用户临时人工复制，不因此提前开发 LM tools 或对话集成。这不是独立 ABC 工具的运行前提。

**非目标（v0.1）**：不做演奏输入捕获与自动评分（自动反馈见 M5，可选）；不集成 AI 对话（长期职责边界，见 §5）；不在 webview 重建编辑器；不做云端与账号；不发出任何网络请求、不收集遥测；不提供 vscode.dev 的 browser 入口。

## 3. 核心循环（学习循环）

1. 用户提出具体目标（如短句即兴，并限制音域、节奏、手部）；
2. AI 给出小型示范，说明本轮练什么；
3. 用户通过谱面与键盘理解音高和节奏；
4. 关闭示范、保留伴奏，用户自己接一句（整段循环播放支撑）；
5. 用户自述结果（"音能找到，但一换节奏就跟不上"）；
6. AI 保留音高材料、只简化节奏——针对同一困难调整，而不是换一份新练习；
7. 隐藏示范与键盘提示，检查能否独立产生句子。

### 可选学习模板（D0 已确认）

工具输入与学习资产分离：任意独立 `.abc` 均可预览、播放，不依赖 AI、个人档案或项目清单。学习模板由用户与外部 agent 维护，插件第一版不解析或自动写回学习档案。

参考结构（目录名与文件名不是插件硬编码要求）：

```text
我的音乐学习/
├── learning-guide.md
├── profile.md
└── exercises/
    └── 001-short-phrases/
        ├── exercise.abc
        └── session.md
```

| 文件 | 最小内容与职责 |
| --- | --- |
| `learning-guide.md` | agent 的阅读顺序、同一练习的调整规则、反馈记录方式、无演奏输入时的能力边界 |
| `profile.md` | 乐器、兴趣、用户自述的能力与困难、练习限制；不放每轮流水账，不用单一 level 概括水平 |
| `exercise.abc` | 当前练习的音乐材料；修改同一练习时保持路径稳定，使已有预览持续更新 |
| `session.md` | 当前目标、练法、关联 ABC；按次追加用户反馈、修改理由、撤除提示后的自述结果、下一步 |

`session.md` 顶部保留“当前进展 / 下次继续”，下方保留历史。记录区分用户自述与 AI 建议，不把建议记成已验证能力。git 保存文件版本，不代替学习记录。

**外部 agent 的使用入口**：用户在对话中指定 `learning-guide.md`、`profile.md` 与当前练习路径，并授权读取、修改相关文件。说明文件不会自动提供权限，也不保证被自动读取。可接入各 agent 的项目指令或 skill，但不依赖某一种专有机制。

**磁盘与未保存内容的边界**：普通文件系统 agent 通常只能读取已保存版本，不能假设其可访问 VS Code 未保存的缓冲区。交给 agent 修改前先保存自己的改动，避免同时写同一文件；外部修改与未保存内容冲突时沿用 VS Code 原生处理，插件不静默覆盖或替用户保存。M0 必须验证外部进程写入后的预览更新，不能只验证编辑器内输入。

## 4. 范围

### P0（M1 工作台 + M2 学习循环）

工作台（M1）：

- `.abc` 文件关联与语法高亮（TextMate grammar）；语言模式为 ABC 的未保存新文档也可主动预览 / 播放，标明尚未保存，临时练习设置仅保留在会话内，不强制保存或新增命令；
- 预览面板：渲染、播放、键盘可视化、变速、本地 soundfont；正常高度采用顶部控制区、中央独立滚动谱面、底部可收起键盘，关键状态位于控制区下方（见设计清单 §3）；
- 尺寸适配：窄宽下常用控件按稳定分组自然换行，进度独占一行，不将循环、速度、声部或隐藏提示收入新的二级菜单。低高度改为内容整体纵向滚动，保留播放 / 暂停、停止与关键状态；键盘不自动收起，其他控件与内容通过滚动访问，放大后恢复正常布局，不改练习偏好。非播放时按宽度防抖重排，播放中保留排版并允许谱面局部横滚；纯布局变化不暂停、不归零、不重新准备音频；到暂停等既定换版时机若有待更新文档，先应用新版并归零再重排，尺寸变化本身不触发换版。方案与线框见设计清单 §3，断点及最小尺寸需 M0 验证；
- 多曲目：同文件一个预览，轻量选择器一次查看 / 播放一首；单曲隐藏选择器，多曲目显示序号、`X:` 与曲名。手动切曲停音、取消旧请求并归零，不自动连播；普通光标不切曲，显式从光标播放才可按可靠映射跨曲。进度、循环、声音与键盘音域仅属于当前曲目，不新增公开命令；
- 键盘默认展开，优先显示整首记谱材料的音域，至少保留两个八度参照，可切换完整 88 键；窄窗口手动横向滚动，播放不驱动键盘横移。仅作可视提示，不提供点击试听；动态提示包含静音的记谱声部，不默认混入自动和弦伴奏，不表示用户真实演奏或必然发声；
- 基础源码 ↔ 谱面定位与播放高亮：查阅 / 播放分离，点击音符不改变播放位置；播放时只跟随谱面滚动，手动滚动后可显式恢复跟随（见设计清单 §3）；
- 加载与恢复：先出谱，首次明确播放时再准备音频；成功后执行仍有效的请求。起播准备中再次普通播放／暂停取消起播并保留最后已提交位置，不提交尚未成功的定位；停止则取消并归零，有待更新文档仍按暂停规则应用。按钮显示“取消起播”并同步可访问名称，命令与局部空格一致；内部缓冲中暂停取消续播。音频失败保留当前谱面及可靠源码定位，用户通过“重试并播放”重新请求，旧结果不得覆盖新请求，不无限自动重试；
- 大材料与等待：自动预览超过软阈值时需“继续预览”确认当前版本 / 曲目，原起播取消，继续预览本身不播放；处理安全硬上限不可绕过，不截断材料或自动拆文件。整文件读取 / 解析、曲目渲染、音频与各格式导出分别限制，保留不受影响的能力。真实阶段提示，较慢时补充说明，各准备阶段超时取消本次任务及相关起播，晚到结果不发布、不发声、不开始写入；同版本、同曲目、同类准备主动取消 / 超时后需明确重试，不因恢复 / 重排自动尝试；合法新请求替代旧任务不触发此限制，用户选择时间不计入计算超时。播放中内部重建超时进入暂停，待更新文档仍按原规则应用。具体阈值与取消能力需 M0 实测，不新增性能设置，详见设计清单 §3；
- 渲染失败：保留明确标为旧版本的参考谱，但不允许旧谱播放或定位新源码；无旧谱时显示错误占位，内容恢复后更新显示但不自动发声。空白文件是正常空状态，不自动填示例，全休止符乐谱不视为空文件；
- 诊断：属于 ABC 内容且有可靠位置的告警 / 错误进入 Problems，无可靠位置的留在预览详情；音频 / 资源错误不标成 ABC 行错误。第三方错误采用本地化摘要与可查看的原始详情，未知原因不猜测，不改变严重性或丢失原文。清理已解决诊断，丢弃过期结果，不自动打开 Problems 或抢焦点；
- 命令：仅公开八个基础命令——预览到侧边、播放 / 暂停、停止并回到开头、从光标播放、从所选音符播放、转到源码编辑、导出 MIDI、导出 SVG；名称、`abcdesk.` ID 与目标规则见设计清单 §2，可在相关上下文发现与自行绑定，不新增默认组合键，也不增加窗口级停止、提示或循环开关的公开命令；
- 命令目标：明确菜单文件 / 所属预览优先，否则使用调用前的活动 ABC 源码或音乐预览；无目标不执行，不回退到最近使用的预览，不弹预览选择器。打开预览命令无目标时可选择文件；源码播放命令可按需创建 / 显示预览，保留源码焦点，仅执行仍有效的起播请求；
- 导出版本与保存：使用执行命令时当前目标文档的内容（含未保存修改），不使用旧播放 / 参考谱面；多曲目每次确认一首，单曲跳过选择，导出选曲不改变预览，不拼接或批量导出。版本差异明确提示，曲目选择期间及写入前发现来源变化则取消并提示重新导出。无预览也独立准备，不要求先播放或加载音色，不主动暂停 / 换版；原生保存对话框确认路径与覆盖，取消不写文件、不代为保存 ABC；
- 导出内容：MIDI 仅按 ABC 材料，不应用播放器的速度、静音、伴奏开关、临时节拍器、当前位置或循环，保留 ABC 本身受支持的音乐指令。SVG 使用稳定排版的白底黑谱，不含键盘、控件与交互高亮，不受主题、窗口宽度或隐藏提示影响；格式完整性、能力降级及保存细则见设计清单 §3；
- 按键与焦点：预览背景 / 谱面局部空格播放，输入框与交互控件保留自身语义；点谱面定位源码但焦点留在预览，从源码起播不转移焦点。Tab / 方向键 / Esc 遵循控件习惯，不设焦点陷阱，自动更新不抢焦点（见设计清单 §4）；
- 播放控制：速度百分比主控（默认 100%，25%～200%，可靠时辅助显示带拍单位的节拍速度），提交变速保持演奏位置、不修改 ABC；进度拖动仅预览目标时间，松手定位，暂停状态下不发声（详见设计清单 §3）；
- 停止停音并回到开头；整段循环开关本身不启动播放；节拍参照保留在范围内（abcjs metronome / drum 参数），入口、默认值及控制语义待 §10 P03 确认；
- 设置与保存：`abcdesk.rememberPracticeSettings` 默认为 `true`，通过 VS Code 用户 / 工作区设置读取；对已保存文档按工作区与完整文档标识保存本地记录。提示显隐、键盘展开 / 音域模式按文件共用；速度、循环、声部静音和自动伴奏开关按可靠曲目身份隔离，不能跨曲复用同名声部设置；不写 ABC 或项目配置、不自动跨设备同步；
- 恢复边界：临时隐藏同一预览时保留选曲及同曲同版本暂停位置；关闭重开 / 重启默认第一首、位置归零，不持久恢复选曲、待起播请求或未提交操作，本次显式跨曲起播不被默认值覆盖。更新后原曲目无法可靠对应则提示重新选择，不按旧序号猜测。更多菜单“重置本文件练习设置”先暂停 / 取消起播，再重置共用界面偏好及该文件所有曲目的音乐设置，不新增公开命令；详见设计清单 §3、§5；
- 文件身份：可靠识别的首次保存 / 重命名在目标无冲突时接续预览与设置，切换先暂停并取消旧请求，不自动续播；目标已有面板或设置时采用目标优先，重新校验实际内容及目标设置，不导入来源记录。来源页若存在则成为迁移提示与显式入口，不再操作旧绑定，不自动关闭或删除记录；只有目标记录时不自动创建目标面板。已有文件另存为仍保持原绑定，新文件主动打开，设置不从原文件复制；无法可靠确认关系时不猜测迁移（见设计清单 §6）；
- 来源不可用：确认文件被删除 / 无法读取且无可用编辑器缓冲区时，保留状态页与仅供参考的旧谱，立即停音并取消起播、禁用旧映射；不自动关闭或重建文件。可用未保存缓冲区不丢弃，原生冲突处理不变；区分外部瞬时替换，来源恢复后重新校验并归零，不自动播放（详见设计清单 §6）；
- 运行环境：声明支持不受信任工作区，受限模式完整可用、不降级、不弹信任请求；首版唯一设置为布尔值，未来路径 / 命令类设置须登记为受限配置。扩展侧只用文档与 `workspace.fs` API、不依赖本机路径或 Node `fs`，Remote / WSL / SSH 兼容，音频与键盘只在本机 webview。完全离线、零遥测，仅内置钢琴音色，其他乐器指令播放统一用钢琴并说明；ABC 文本一律文本渲染，CSP 不放行远程域，webview 消息按类型 / 范围 / 文档版本校验（详见设计清单 §7）；
- 激活与存在感：仅 `onLanguage:abc` 加 `contributes.commands` 自动生成的命令激活，不用 `workspaceContains` / `onStartupFinished`，激活不创建预览、不加载音色、不弹通知；不加状态栏项；不做 walkthrough 与首次通知，功能发现靠编辑器标题栏按钮、`.abc` 右键、命令面板前缀与 README（见设计清单 §2、§3）；
- 本地化与文案：自有 UI 英文默认并同步提供简体中文，跟随 VS Code 显示语言；缺译或未支持语言回退英文，不新增语言设置或命令。覆盖命令、菜单、设置说明、控件、状态 / 错误、导出提示与无障碍标签；技术标识及用户音乐内容保持原文。短句说明动作、影响与可用下一步，区分暂停、停止、隐藏提示与静音；第三方错误保留原始详情，不在线翻译（见设计清单 §8）。

学习循环（M2）：

- 示范 / 伴奏切换：通过带静音摘要的折叠声部菜单控制实际 ABC 声部，不强制第一声部为示范；`voicesOff` 按选定声部关闭发声，显式伴奏声部可保留；`chordsOff` 独立控制自动和弦伴奏轨（待听验后定型）；
  - 第一版先暂停再调整，菜单提供“暂停以调整声部”入口，自动和弦伴奏开关同样处理；无文件更新时保留演奏位置，调整后手动播放。暂停时若有新版本，先更新并回到开头，再调整新版本声部。
  - 静音恢复采用保守规则：先确认同曲身份，再核验声部有序清单，未变时保留；声部增删、改名、改标识、重排或无法确认时清除该曲目旧静音覆盖并提示，不部分继承、不影响其他设置或其他曲目。曲目身份不可靠时不恢复其历史音乐设置，界面偏好仍按文件恢复。自动和弦伴奏按曲目独立保存；暂时空白或解析失败不擦除声部记录，只在有效新版本应用时比较。
- 独立“隐藏提示 / 显示提示”按钮：隐藏谱面与键盘，保留播放控制与状态，不改变声音；恢复之前的显示状态，不影响原生源码页；
- 可选的学习资产模板与通用 agent 说明（见 §3），不绑定特定 AI 产品或专有指令文件；
- 反馈记录：用户自述 → 用户 / 外部 agent 更新 `session.md`（纯文件，无插件管理 UI）；
- 练习约束检查（少量确定性检查：小节时值、音域、音符密度；区分"技术检查通过"与"教学质量确认"）。

### P1（后置，验证学习价值后）

- TreeView（会话 / 练习库）、LM tools（`validateAbc` / `renderAbc` / `playAbc`）、选区循环、练习库元数据约定。

### 明确不做（v0.1）

见非目标；另含：自定义谱面编辑器 UI、Markdown 内 abc 代码块（评估后置）、整份曲集连续展示 / 自动连播、整集拼接或批量导出、自动拆分曲集、超限自动截断材料、安全硬上限绕过入口与用户性能调参设置、远程音色库 / 在线服务、受限模式功能降级清单、状态栏项、首次使用 walkthrough / 首启通知（walkthrough 归 M4 再评估）。

## 5. 已定架构决策

1. **格式**：ABC 是主要的音乐记谱交换格式；教学说明与反馈使用自然语言，必要约束使用结构化数据。复杂演奏表现不强行简化为记谱内容。
2. **宿主**：VS Code 为首要实验载体，不预先认定为最终产品形态；Web Studio 保留为未来练习 / 演奏端候选。
3. **反馈三层分工**：插件 = 环境与桥接（文件、预览、播放、命令、诊断、调用外部工具）；计算 = 插件外（仓库脚本 → VS Code Task → MCP → 最后才考虑内嵌）；教学法 = 提示词 / 工作区资产。**数据契约先行**，实现位置可后移。
4. **职责边界**：扩展宿主（Node）不处理音频；音频与键盘可视化只存在于 webview。
5. **仓库策略**：新建独立仓库，理由为独立发布 + 旧仓库冻结（保证只有一个活跃副本，无分叉成本）；构建工具差异不作为主要理由。若未来 Web 端复活，再抽取共享包。
6. **伴奏路线**：优先使用 abcjs 内置能力（和弦符号轨 `chordsOff`、声部开关 `voicesOff`、节拍器），不自建伴奏引擎；伴奏风格与织体需 M0 听验。键盘按记谱材料提供提示，包含静音声部，不默认纳入自动和弦伴奏；M0 验证提示与记谱演奏时间一致，不要求所有亮键都有声音。
7. **工期**：所有周期均为待验证估计，不能仅凭现有播放器代码确认迁移与 P0 按期完成。
8. **预览形态（D0 已确认）**：保留原生 ABC 文本编辑器，音乐界面使用 Editor 区独立预览页；支持源码与预览并排，也支持只显示预览练习，不要求源码标签页一直打开，不另建练习模式页面。第一版不注册 Custom Editor。预览标明来源文件，切到学习记录或 AI 对话不丢失当前练习。
9. **预览入口（D0 已确认）**：由用户通过编辑器标题栏按钮、命令面板或资源管理器 `.abc` 右键菜单主动打开到侧边。主动从 ABC 源码播放或从光标播放时，也允许按需创建 / 显示对应预览，保留源码焦点；有效渲染与音频准备完成后执行仍有效的请求，不在隐藏面板中后台发声。第一版不提供被动自动打开设置；打开文件、切换编辑器或外部修改不打开预览，关闭后不因文件修改重新弹出。已有预览非播放期间按文档变化自动更新（含未保存修改），并受第 19 条的大材料确认及取消 / 超时规则约束；播放期间按第 13 条延后更新，更新本身不自动起播。恢复先前已打开的预览不视为自动新建。
10. **文件关联（D0 已确认）**：每文档绑定预览，同文档在同一 VS Code 窗口内复用，包含语言模式为 ABC 的未保存新文档；切换活动编辑器不改变绑定。主动预览其他文件时打开其独立预览，不替换当前练习；第一版不增加跟随 / 固定开关。可靠的首次保存 / 重命名在目标无冲突时接续原预览和设置，先暂停并取消旧请求；目标已有状态时按第 20 条处理，已有文件另存为不改变原绑定或复制设置。来源确认不可用且无可用缓冲区时保留状态页并立即停音，不继续旧播放快照；不猜测路径关系、不丢弃未保存编辑。细则见设计清单 §6，多预览播放互斥及面板隐藏规则见第 13 条。
11. **AI 职责与学习资产（D0 已确认）**：插件不集成 AI 对话，对话由具备文件系统访问能力的任意外部 agent 提供，不绑定 VS Code 内 AI 或特定产品。使用普通文件协作；学习资产为可选轻量模板（见 §3），由用户 / agent 维护，不成为独立 ABC 工具的运行前提。LM tools 等工具接口仅为后置增强，不承载对话，也不成为文件协作的依赖。
12. **基础联动（D0 已确认）**：查阅位置与播放位置分离；点击谱面音符只选中并定位源码，焦点留在预览、不改变播放位置，显式“转到源码编辑”才转移焦点。通过“从光标 / 所选音符播放”定位起播，从源码执行时保留源码焦点；具体进入与恢复原则见设计清单 §4。播放时只跟随谱面滚动，源码只高亮、不滚动、不移动编辑光标；用户手动滚动谱面后暂停跟随，可显式恢复。不因播放打开源码页或恢复已隐藏提示。反复音符默认起播落点仍待 §10 P02 确认，多声部映射能力需 M0 验证，详见设计清单 §3；源文档与播放版本不一致时，源码联动按第 13 条暂时禁用。
13. **音频生命周期（D0 已确认）**：播放中普通内容变化时保留当前音乐与谱面版本并提示待更新，文件身份迁移与来源不可用的中断规则见第 10 条；立即暂停源码联动并清除源码播放高亮，避免旧位置映射到新文本。暂停、停止或自然播放结束后应用最新内容，重置位置，不自动起播；普通暂停且无内容变化时保留位置，循环回到开头不触发更新。失焦继续播放，面板隐藏则暂停，恢复后不自动播放；仅隐藏谱面 / 键盘提示不暂停。新预览起播前先暂停旧预览，同一窗口内只允许一个预览发声；隐藏及接替导致的暂停也应用待更新规则。关闭预览停止音频并释放资源；启用设置记忆时重开 / 重启恢复每文件练习设置，但播放位置归零，不恢复待起播操作。临时隐藏且同版本的暂停位置只在同一面板生命周期内保留。最新渲染失败时保留旧谱参考并禁用其播放与源码映射；若当前谱面有效、仅音频失败，则保留谱面及可靠源码定位，用户可“重试并播放”；普通解析告警不一律禁止播放。首次明确播放才准备音频，只有仍有效的播放请求可在准备成功后发声；准备中再次普通播放／暂停取消起播并保留已提交位置，停止取消并归零，有待更新内容时暂停换版规则优先。不把内容恢复或界面恢复当成播放请求，旧取消回调不得清掉之后的新显式请求。播放中的变速 / 定位可内部重建后继续当前快照，不视为用户暂停或触发文件换版；期间出现暂停、停止、隐藏、关闭或播放接替时必须取消续播。内部准备失败或超时则进入暂停并取消续播，同版本保留最后可靠的已提交位置，有待更新文档则按暂停规则应用并归零；具体等待与限制见第 19 条，状态与验证要求见设计清单 §3、§5。

14. **曲目边界（D0 已确认）**：文件绑定不变，预览内部选曲；一次一首，切曲停音归零，普通光标不切曲，显式从光标播放可跨曲但不绕过待更新规则。音乐设置以可靠曲目身份隔离，界面偏好按文件共用；当前选曲仅在本次预览中保留，重开默认第一首。文档重排 / 删除后无法可靠对应则要求重新选择，不使用旧下标猜测；导出从当前文档每次确认一首且不改预览。曲目解析须继承公共头部并保留整文件源码映射，具体身份来源与异常边界在 M0 验证。
15. **运行环境与安全边界（D0 已确认）**：受限模式完整支持、不降级，ABC 仅作数据解析，不读取路径 / 外部程序 / URL / 脚本类设置，首版唯一设置为布尔值；未来新增路径类设置必须登记为受限配置或重新确认声明。本地优先、Remote 兼容：扩展侧不依赖本机路径与 Node `fs`，只用文档与 `workspace.fs` API，资源仅经 `asWebviewUri`，音频与键盘只在本机 webview；vscode.dev 不承诺、虚拟工作区不作目标也不主动禁用。完全离线、零遥测：不发任何网络请求，仅内置钢琴音色，abcjs 默认远程音色地址不得触发；远程音色库 / 在线服务为独立后置决策（显式开关、默认关闭）。不受信任内容一律文本渲染，CSP 仅放行 nonce 自有脚本与扩展资源，扩展侧不信任 webview 消息。细则见设计清单 §7。
16. **激活与存在感（D0 已确认）**：激活事件仅 `onLanguage:abc`，命令由 `contributes.commands` 自动激活（VS Code 1.74+）；不用 `workspaceContains`、`onStartupFinished` 或 `*`，未打开 ABC 的工作区零开销。激活本身不创建预览、不加载音色、不弹通知。首版不加状态栏项，不做 walkthrough；“仅发声时显示状态栏”与 Get Started 页分别留待自用实验与 M4 再评估。
17. **本地化与文案（D0 已确认）**：英文默认 + 简体中文，覆盖全部首版自有 UI，统一跟随 VS Code 显示语言，未支持语言或缺译回退英文，不增加语言设置。声明式贡献、扩展提示与 webview 分别接入打包的本地文案资源，Remote 不采用远端系统语言；不以显示文字作消息类型、状态枚举或持久标识。短句与明确动作统一语义；第三方错误使用可靠分类的本地化摘要与原始详情，未知原因按失败阶段概括，不猜测、不在线翻译。商店材料、完整双语文档与其他语言仍后置；具体资源结构与错误映射待实现验证。
18. **窄宽、低高度与重排（D0 已确认）**：常用控件分组换行，进度独占一行；高度不足时仅核心播放控制与关键状态驻留，其他内容整体纵向滚动，不自动收起键盘或修改显隐偏好。滚出视口不等于面板隐藏，不触发暂停；用户手动浏览仍可暂停谱面跟随。非播放时适配谱宽，播放中保持排版、必要时谱面局部横滚；暂停后采用最新宽度，纯尺寸变化保留选曲、设置与演奏位置，不准备音频、不起播。文档更新优先按第 13 条处理，重排不得借机解除旧版本映射禁用或改变独立 SVG 导出布局。尺寸断点、布局请求校验与映射衔接需 M0 验证。
19. **性能保护与等待（D0 已确认）**：软阈值限制自动预览，确认仅对当前文档版本 / 曲目的预览有效，不授权起播；硬上限按处理阶段判断，所有显式操作同样遵守，不提供绕过、不截断材料。输入规模之外还检查事件展开、有限演奏时长与音频缓冲成本，避免先无界计算再判断超限；音频受限不自动禁止有效谱面或独立导出。准备较慢时说明阶段，超时终止请求，取消后结果不得发布或发声；同版本同曲目的同类准备主动取消 / 超时后需明确重试，不因重建 / 重排自动重试，也不堆积旧重任务；合法新布局请求替换旧任务不视为用户取消，不阻止最新请求正常执行。计算超时不包含用户选择时间或正常播放时长，导出准备取消与已经提交的文件写入分开，后者不承诺回滚。仅重排取消 / 超时可保留同版本有效谱面与映射；新版预览未通过时旧谱只供参考。阈值、实际取消响应、资源释放与本地 / Remote 表现需 M0 验证，不新增设置或公开命令。

20. **准备期间控制与迁移冲突（D0 已确认）**：起播准备中再次普通播放／暂停（按钮、命令、局部空格）取消起播并保留最后已提交位置，不补交尚未成功的定位；停止仍归零，内部缓冲中暂停取消续播，有待更新文档按原暂停规则应用。按钮显示取消含义并同步可访问名称。可靠首次保存 / 重命名遇目标已有面板或设置时，暂停受影响预览并取消旧请求，目标面板及经校验的目标设置优先；无效目标记录按默认值回退，不混入来源设置。来源面板若存在则保留为迁移状态页，不再执行旧绑定的播放、定位、设置修改或导出，只能显式进入目标；仅有目标记录时不自动建面板，没有来源面板也不新建状态页。不自动关闭页面、删除来源记录、抢焦点或续播；没有可靠关系时不猜测迁移，另存为规则不变。行为及状态转换见设计清单 §2～§6，剩余设置边界见 §10。

### 从 chatmusic 平移：复用与适配

**复用（实质基础）**：`src/player/**` 的播放事件驱动高亮、源码字符范围回调、点谱面定位播放、本地钢琴音色、变速与进度控制；`src/shared/abc-quality/**`；`abc-midi-export.ts`、`abc-file.ts`、`filename.ts`；`public/soundfonts/**`。

**需要适配（平移不等于直接复用）**：

| 适配点 | VS Code 中需要处理的内容 |
| --- | --- |
| 渲染入口 | 分离宿主行为（扩展消息、网页代码块、源码折叠），接入 webview 消息桥 |
| 响应式布局与重排 | 分组换行与低高度整体滚动，区分面板隐藏和内容滚出视口；谱面只在非播放时按最新宽度重排，布局请求与文档更新分开，重关联节点与可靠映射，不因尺寸变化重置位置或音频 |
| 曲目选择 | 现有播放与 MIDI 导出直接取首个曲目，需改为明确选曲；继承公共头部，维护曲目范围到整文件的源码偏移，不把数组下标当持久身份 |
| 资源路径 | `asWebviewUri` 与相应 CSP；Remote 下音色经 webview 资源通道加载，扩展侧不用 Node `fs` 或本机绝对路径 |
| 音色策略 | 保留仅本地钢琴音色的强制路线，确认 abcjs 默认远程音色地址在任何指令下不被触发；`%%MIDI program` 播放统一钢琴并说明 |
| 文件导出 | 改接扩展侧选曲确认、原生保存流程与写入前版本校验；从当前文档独立生成所选单曲，不依赖预览或音频就绪；MIDI 隔离播放器设置，SVG 使用独立白底黑谱布局并清除交互标记，不能只序列化第一个可见 SVG |
| 联动接口 | 补充编辑器光标 → 谱面定位能力；将现有点谱面定位播放行为拆为查阅定位与显式起播，避免点击查阅改变播放位置 |
| 播放控件 | 百分比范围改为 25%～200%，输入提交后变速；进度从拖动中持续定位改为松手提交；声部先暂停再调整，内部重建与用户暂停分别处理 |
| 播放映射 | 验证反复记号等一段源码对应多个播放位置的映射；首次出现仍只是推荐，默认落点待 P02 确认；多声部按当前静音设置播放，无映射时提示 |

### 里程碑原则

- 工作台完善不阻塞首次学习实验：进入 M2 只要求核心路径可用（渲染、播放、基本联动），导出、诊断完善、边角交互等打磨项并行后补。
- 学习实验优先于产品化打磨（与 §1 质量基线不冲突：基线仍从第一天执行）。

### M2 出口：端到端练习验收脚本

起点要求：选择一个符合当前能力的小目标（如 C 大调、单手五指内、两小节短句接续），写入 `profile.md`；`exercise.abc` 含示范与伴奏。

1. AI 给出小型示范（≤2 小节），说明本轮只练什么；
2. 用户听示范，通过谱面与键盘理解音高和节奏；
3. 暂停后静音示范、保留伴奏，再手动播放；示范的谱面与键盘提示仍按时间显示，用户自己接一句（整段循环播放）；
4. 用户自述一个具体困难（例："音能找到，但一换节奏就跟不上"）；
5. AI 保留音高材料、只针对该困难修改同一练习；
6. 撤除提示（隐藏谱面与键盘高亮）后再尝试；
7. 结果记录到 `session.md`（目标、练法、反馈、下一步）。

跨会话验证：第 2 次会话中，AI 读取 `session.md` 并续接上次的目标与困难。

通过判定：以上步骤真实发生且可复现；仅"生成谱面并播放成功"不算通过。

3. 播放出声：本地 soundfont 加载成功，不依赖网络；先出谱、首次明确播放才准备音频，完成后执行仍有效的请求。准备中再次普通播放／暂停取消起播并保留最后已提交位置，不补交未完成的光标 / 进度定位；停止取消并归零，有待更新文档按暂停规则应用。覆盖取消后迟到成功 / 失败、取消后立即发起新的显式请求，旧回调不能发声或覆盖新状态。模拟音频准备失败，验证当前谱面及可靠联动保留、“重试并播放”的显式起播与取消、无无限自动重试；隐藏、关闭、接替或目标版本失效后旧任务不得发声。记录首次等待与缓存复用效果；
4. 非播放期间编辑文件后预览按软阈值确认、主动取消 / 超时及防抖规则更新；播放期间修改则保持旧音频与旧谱一致，立即停用源码联动并提示待更新；暂停 / 停止 / 自然结束后应用最新内容，重置位置但不自动播放。验证连续写入、循环不切版、无变化时暂停保留位置；覆盖空白、合法全休止符、普通告警、首次渲染失败及更新失败保留只读旧谱，恢复有效内容不自动播放或显示已隐藏提示。验证防抖等待中不用旧源码映射、Problems 仅关联可靠的当前文档位置、旧诊断清理与过期任务丢弃，音频错误不误标为 ABC 行错误；

10. 外部 agent 协作与文件生命周期实测：

    - 内容与消息：标题、声部名、告警含 HTML / 脚本片段时只显示文本；CSP 白名单仅含 nonce 自有脚本与扩展资源；含 `%%MIDI program`、外部资源类指令的 ABC 不触发任何加载；扩展侧拒绝缺类型、越界范围、版本不符或含任意路径的 webview 消息。按第 19 项测定超大 / 畸形输入阈值与取消响应，验证信任与受限模式同样保护，不冻结界面。
    - 零网络：打开、播放、导出全程在开发者工具网络面板确认无外部请求，含 abcjs 默认远程音色地址。
16. 激活验证：未打开 ABC 的工作区启动后扩展不激活（Running Extensions 面板核对）；打开 `.abc`、资源管理器右键执行命令、命令面板执行命令三条路径均能激活并正常工作，右键菜单与标题栏按钮在激活前已可见。激活不创建预览、不加载音色、不弹通知；记录激活耗时与打包体积，确认音色不在激活时读入。
17. 本地化路径验证：使用代表性文案，在英文、简体中文及一个未支持语言环境下检查菜单 / 设置、扩展提示、webview 三条路径；语言统一跟随 VS Code，未支持语言与缺译回退英文，不显示资源键或空标签。检查本地资源打包、带参数文案、安全文本及无外部请求；Remote 冒烟中核对语言不随远端系统变化。验证已知 / 未知第三方错误均有真实摘要与可查看的原始详情，无预览导出也能查看而不强制开预览，不因本地化改变诊断位置、严重性或可用操作。M0 只验证路径与代表性文案，M1 完成全量中英覆盖。
18. 尺寸适配与重排验证：
    - 覆盖宽高充足、窄而高、宽而矮、又窄又矮四类面板，记录实际 CSS 尺寸、断点、最小可用范围与防抖值。常用控件换行而不新增二级菜单，进度独占一行；低高度整体滚动时核心控制与关键状态可见，其他控件、谱面与键盘可访问，无整页横向溢出，不自动收起键盘或改写偏好。
    - 播放中连续改变宽度不重排、不打断音乐，必要时谱面局部横滚；暂停后按最新宽度重排并保留同版本演奏位置，停止本身仍归零。与文档更新并发时播放仍保持旧快照，到暂停 / 停止 / 自然结束时先应用最新内容并按原规则归零，再适配宽度；检查新谱面节点的查阅 / 播放标记、源码映射以及独立 SVG 导出不受预览尺寸影响。
    - 验证低高度往返、手动滚动与跟随、焦点 / 菜单 / 输入 / 拖动，以及重排中起播、隐藏、切曲与关闭。尺寸变化不提交旧输入或旧拖动，不恢复被用户暂停的跟随；过期布局结果不覆盖新曲目或新一轮播放。结合中英长文案、VS Code 缩放、错误状态、多曲目和 88 键实测，M1 完成布局巡检；无法保持边界时记录证据并回到设计确认。
19. 性能保护、等待与取消验证：
    - 样本包含正常短练习、大曲集、长单曲、多声部、高密度事件、大量反复、极慢速度与畸形输入。在本地与 WSL / SSH 之一记录输入规模、解析 / 渲染 / 音频 / 各格式导出的耗时、峰值内存和取消响应；测定软硬阈值、较慢提示时点、阶段超时与防抖值，标明测量环境，不把阈值或预计耗时当作跨机器性能保证。
    - 软阈值只暂停自动预览，确认核验当前版本与目标曲目，不跨版本授权；从源码播放遇到确认门槛时取消原起播，继续预览不发声。覆盖连续外部写入、缩小材料后自动更新与播放中待更新；不反复弹窗，不因性能提示提前换版。硬上限同样约束显式播放 / 重试 / 导出，不绕过、不截断或自动拆文件；检查前不无界解析、展开事件或分配音频缓冲，播放器循环不无限展开。
    - 控制各阶段延迟，验证正常完成、慢提示、取消、超时与迟到成功 / 失败；取消入口可聚焦、可操作，不因隐藏提示或窄矮布局不可见。超时或取消后旧任务无谱面 / 诊断回写、无意外发声、无后续导出写入；同版本同曲目的同类准备主动取消 / 超时后不因面板恢复 / 尺寸变化自动重试，合法新布局接替旧任务不误触发此禁用，其他能力不被连带禁用，连续重试不堆积旧计算。除结果失效外，验证同步重计算可中断、界面可响应、资源可释放；仅计时器或 Promise 竞速不足以通过，无法实现时记录证据并回到设计确认。
    - 覆盖当前谱面有效但音频受限、整文件解析超限、新版渲染取消与仅布局重排取消；正确保留当前能力或旧谱参考，不混淆源码映射。播放中变速 / 定位失败或超时进入暂停，同版本保留最后可靠位置、有待更新文档则应用并归零；隐藏、关闭、切曲、接替与超时并发时旧任务不能续播。
    - 无预览导出也有等待与取消，不加载音色或改变播放器；音频超限时按格式独立判断。用户在材料确认 / 曲目选择 / 保存对话框中停留不消耗计算时限，返回后校验任务与来源再写入；准备取消 / 超时不得开始写入，已提交写入只报告真实结果，不误报撤销、不自动重写或回滚。

### M1 导出验收补充

以下为工作台导出交付要求，完善不阻塞 M2 首次学习实验：

- 目标与版本：覆盖未保存新文档、已有文件未保存修改、无预览、旧快照播放中、音频失败及来源不可用；多曲目每次确认一首，列表、预选与输出归属一致，单曲跳过列表。不回退旧谱，不代为保存 ABC，切换焦点或预览选曲不改变已确认导出目标；选曲 / 保存对话框期间内容变化、重命名或来源失效时，开始写入前取消并提示重新导出。
- MIDI：改变播放器速度、静音、自动伴奏与临时节拍器后，导出仍遵循所选曲目的同一 ABC 材料，包含适用的公共头部指令；不夹带其他曲目、不从当前位置截取或展开播放器循环。验证记谱反复、多声部、曲中速度与受支持 MIDI / 伴奏指令及缺省行为，记录不支持项；用独立 MIDI 查看器 / 播放器核对事件和时长，不把音色相同作为条件。
- SVG：浅色 / 深色 / 高对比度、不同窗口宽度和隐藏提示下，均得到稳定布局的白底黑谱，无播放 / 选择高亮；长谱完整，不仅截取首个 SVG。脱离 VS Code 可读，不依赖宿主 CSS 或临时 URL，不携带脚本和不必要的路径信息；仅输出用户确认的曲目但包含其完整谱面及适用公共指令，不能错误输出第一首或混入其他曲目。
- 保存与失败：核对默认文件名、路径选择、覆盖确认、取消、写入权限错误及来源保护；只在写入成功后报告成功，不自动打开文件或起播。空白不生成空壳，全休止符不视为空白，普通告警不一律禁用；按格式判断能力，不把音频错误或文件权限错误混作 ABC 行错误。任务结束释放临时资源，旧任务不覆盖新任务结果。

## 8. 连续自用实验的判定（M3）

**判定优先级：学习结果 > 操作体验。** 只要学习结果成立（即使体验不完美）就继续；只有当操作成本明显挤占练习时，才优先投入体验改进。

**观察维度**

| 维度 | 需要回答的问题 |
| --- | --- |
| 操作成本 | 琴前时间主要花在演奏，还是切回电脑、编辑代码、修复 ABC？ |
| 适配质量 | 用户反馈后，下一轮是否针对同一个困难调整，而不是随机换一份练习？ |
| 独立表现 | 关闭示范与键盘提示后，能否产生自己的句子，而不只是跟随？ |
| 跨会话延续 | 下次练习能否延续上次的目标和困难，而不是每次重新开始？ |

**分支条件**

- 音乐交流顺畅、琴前操作可接受 → 继续投入 VS Code 插件；
- 音乐交流顺畅、但琴前操作明显不便 → 评估简化的 Web / 平板练习端，不重做整个系统；
- 反馈不能有效改变下一轮练习 → 优先调整教学说明、约束与记录方式，而不是继续加功能；
- 只能复现示范、无法独立变化 → 调整练习设计（留白、变奏、限制条件、提示撤除）。

## 10. D0 决策进度与后续细化

第一批五项主决策已确认：预览形态、入口与打开方式、文件协议与可选学习模板、基础联动、音频生命周期（播放中保留当前版本、暂停后更新；失焦继续、隐藏暂停；新播放接替旧播放）。外部 agent 对话边界与文件协作规则亦已确认，见 §3、§5。

第二批已确认：正常高度采用顶部控制、中央独立滚动谱面、底部可收起键盘，低高度采用下述整体滚动例外；声部控制采用折叠菜单与静音摘要，隐藏提示采用独立按钮；速度百分比主控（25%～200%，默认 100%）、进度松手定位、声部先暂停再调整并手动播放。停止停音并回到开头，循环开关不启动播放。

键盘已确认：首次默认展开，乐曲音域优先、至少两个八度参照，可切换完整 88 键；同版本音域稳定，窄窗口手动横滚。提示包含静音记谱声部，不默认混入自动和弦伴奏；第一版仅作可视提示，不提供点击试听。默认布局线框与行为见设计清单 §3，具体按钮文案与尺寸尚未锁定。

按键与焦点已确认：空格仅在预览背景 / 谱面局部控制播放，交互控件保留自身语义；点击谱面定位源码但焦点留在预览，显式转到源码编辑才转移焦点。第一版提供可发现、可自行绑定的核心命令，不新增工作台级默认组合键。进入、恢复、Tab / Esc 与不抢焦点原则见设计清单 §4。

加载、错误与空状态已确认：先出谱，首次明确播放才准备音频；准备成功后执行仍有效的请求。准备中再次普通播放／暂停取消起播并保留已提交位置，停止取消并归零；内部缓冲中暂停取消续播，有待更新文档按暂停规则应用。最新渲染失败保留只读旧谱参考；当前谱面有效但音频失败时保留谱面及可靠联动，用户显式“重试并播放”。空白文件不报红、不自动填入示例，全休止符不视为空白；内容诊断与音频 / 资源错误分开，旧诊断及时清理。主要状态表与逻辑线框见设计清单 §3。

工作名与基础命令已确认：新插件称 ABC Desk，公开命令使用 `abcdesk.` 前缀；仅八个基础命令，不增加窗口级停止、提示或循环切换命令。明确文件 / 预览优先，否则使用调用前的活动音乐上下文；无目标不执行、不猜测最近预览。源码播放可按需创建 / 显示预览并保留源码焦点，与被动自动打开区分。名称、ID 与目标规则见设计清单 §2；品牌可用性未核验，不重命名旧浏览器项目。

设置与恢复已确认：按工作区和完整文档标识本地记住练习设置，记忆开关默认开启，更多菜单可暂停后重置，不新增公开命令；关闭重开 / 重启后播放位置归零，不恢复待起播操作。临时隐藏仍保留同版本暂停位置。声部有序清单可靠且未变才恢复静音，变化或无法确认时清除旧静音覆盖并提示，不影响其他设置；暂时空白 / 解析失败不擦除记录。保存明细、默认值和边界见设计清单 §5。

文件生命周期已确认：未保存新文档设为 ABC 即可临时预览与播放，设置仅存当前会话；首次保存 / 重命名关系可靠且目标无冲突时接续预览与设置，切换先暂停 / 取消，不自动续播。有目标冲突时采用第 20 条的目标优先，来源页仅保留迁移说明与显式入口，不操作旧绑定或混入来源记录，不自动关闭页面、删除记录或新建目标面板。已有文件另存为保留原预览绑定，新文件独立设置。来源确认不可用且无可用缓冲区时保留状态页并停音，旧谱仅供参考；保留未保存编辑，区分外部瞬时替换，来源恢复不自动播放。具体规则、状态表与线框见设计清单 §2、§3、§6。

基础导出语义已确认：使用当前文档（含未保存修改），有版本差异时明确提示，不主动暂停或替换播放快照；MIDI 仅按 ABC 材料，不受播放器练习设置影响；SVG 使用稳定布局的白底黑谱，不带交互标记。原生保存对话框确认路径与覆盖，取消不写文件、不代为保存 ABC；写入前发现来源变化则提示重新导出。无预览独立生成路径需 M0 验证，M1 完成格式与保存验收，见 §7 和设计清单 §3。
